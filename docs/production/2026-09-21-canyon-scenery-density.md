# 峡谷场景密度修订：从悬空台阶到机械遗址

状态：用户“很单调”后的制作约束，尚未实现或验收。与内容密度扩充同时推进，不取代新敌人、机关、动作及最终素材目标。

## 已见事实

本次再次查看正常渲染证据 `task10-gear-entry-rendered-2350-20260921T083527879-63f0cbb61da948459af697b0b2c9dc7b/review-frames/frame-10.png`：齿轮区角色/台面边缘清楚，但背景主要为大块暗青底色、几只放大的齿轮；多块金属台面呈独立盒子，缺少能说明用途的机械结构。顶部与中央有大面积没有视觉事件的平面。此为固定帧率局部采样，不能代表所有场景或整段运动。

源码中十二个 `CompositionId` 的确指向不同绘制分支，但这只证明分支存在；不同名称、代码配方或背景颜色不证明十二种有趣空间。原有薄台面与同节奏接缝在多个区域重复，缺少近中远比例变化。

## 制作决策

先以低成本、可替换的原生结构绘制改善构图，不下载素材、不付费生成、不把程序图元冒称完成的原创手绘。把视觉细节集中在可解释的用途上，而不是均匀撒颗粒。

| 区域 | 必须形成的视觉场所 | 重点物件与构图 | 保留的安静空间 |
| --- | --- | --- | --- |
| 入口与横跳裂隙 | 曾经使用过的运送入口 | 一侧残破门架、断裂运送梁、压暗的吊篮与破旗；裂隙墙面呈错层切面 | 玩家起跳、前方落点、首次敌人预警 |
| 深渊 | 纵深明显的废弃吊运井 | 岩层断面、跨层承重架、不同长度的悬缆；底部残骸与上方空间有尺度差 | 中央下落走廊、制动墙和侧出口 |
| 档案与冰封支路 | 可探索的遗留工作空间 | 倾斜档案架、残缺铭牌、倒伏容器；冰封段改为冷色矿缝与封冻管线 | 可抓/不可抓材料边界、支路返回方向 |
| 盆地与齿轮区 | 埋在峡谷中的检修车间 | 齿轮连接轴承机架、低对比支承斜梁、嵌壁检修凹室、断管与局部暖光 | 安全营地；护盾走廊、活塞前摇和落脚边 |
| 配重/摆锤/上升回廊 | 多层机械钟楼 | 配重槽有分段导轨；钟体有宽口、狭冠、缺口等不同轮廓；层叠廊架与凹室 | 实际摆锤路径、飞行敌人轮廓和机械爪目标 |
| 神殿 | 有目的地感的遗迹终点 | 破拱、层层门楣、背光凹龛、残柱与低饱和铜紫层次 | Boss主体、攻击主形、战后实体出口 |

## 不允许用来填空的做法

- 不在可通行的空洞内画出与实际台面等亮的横梁或地板；支架必须低对比且在玩法层之后，不能冒充落点。
- 不新增大幅前景遮挡，不覆盖角色、提灯、怪物前摇或落脚边。旧跨区前景遮挡修复不得倒退。
- 不改通用 `CoverageLayer` / `DrawContinuousDistantField` 的世界对齐逻辑，不用按区不透明底色重造跨区接缝。
- 不改真实碰撞、可抓材料、机关位置、攻击时间线或存档来适配装饰。功能轮盘、可抓靶和实际危险不能混入背景同色符号。
- 不用高频噪点、满屏粒子、整体纹理拉伸或大量同尺寸齿轮补密度。画面丰富需要大小、疏密和用途的区别。

## 第一轮实现边界与检查

首选实现入口是 `CanyonBackdropVisual` 的 challenge/sector 结构绘制，以及 `CanyonPlatformVisual` 的内部台面分区；通用覆盖底色、真实 ReadableEdge、CatchShelf 语义和所有玩法数据保持不变。先改机械区及上升区最显眼的重复，再把同一深度/对比原则应用于入口、深渊和神殿，不能只改一处就称全图精修。

每次实现前后保存同镜头、同角色位置和同显示设置的正常窗口对照，至少检查入口、深渊、盆地、上升回廊和神殿；局部视觉布景测试允许明确标记的镜头采样，不冒充从开局连续游玩的录像。另保留正常移动中的跨区片段检查接缝与遮挡。执行既有 builder/packed readability、material skin、art-removal 和真实触发回归。测试清单只能证明结构与可读性，最终观感由实际画面复核。

最终美术质量、披风/敌人动作、UI统一和整关视听仍未完成。若结构改良后仍明显是简陋代码图形，应明确缺失的原创素材，进入独立素材制作决策，而不是继续堆图元并宣称达到手绘成品标准。
