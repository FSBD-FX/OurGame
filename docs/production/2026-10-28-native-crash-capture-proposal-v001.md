## 安装与一次性采集顺序

1. 确认方案后，先从[微软 ProcDump 官方页](https://learn.microsoft.com/en-us/sysinternals/downloads/procdump)下载便携ZIP，校验Microsoft签名、记录版本和SHA256，解压至 G:/knight/Tools/ProcDump/。官方页面现列ZIP约1.2MB；无需先装完整SDK。许可先呈现给用户，不静默使用 -accepteula。若无有效签名或需要提权，停止该步骤并报告，不绕过。
2. 固定当前源代码、引擎、程序集及PDB的版本和哈希。使用原测试入口建立一次独立StorageRoot，不读取或修改真实玩家存档；先验证采集接入方式符合原PID、限时和证据归属规则，再执行。ProcDump只附加本次隔离引擎的精确PID，并复核CreationTime、路径和参数；不按所有Godot进程名附加，不接管编辑器或其他应用。
3. 只在未处理原生异常时产生至多1份Full dump（拟用 -ma -e -g -n 1，执行前按已下载版本help复核）。不启用first-chance泛捕获，不注册系统默认调试器，不设WER上传、后台服务、计划任务、自启动或循环重试；不增加GC/资源强引用，不改变引擎与真实存档。原测试时间上限保持；若写转储未在既有边界内完成，报告采集未完成，不自行延长或重跑。
4. 新建唯一日期/主题/版本目录 G:/knight/原生诊断/<日期_主题_版本>/，保存dmp、采集器原始输出、该案例日志与精确模块/PDB哈希、PID/CreationTime、参数和来源索引。执行前预留数GiB并检查进程规模；不足就先报告，绝不删除旧资料腾空间。只有这一个测试进程；不抢占前台或发系统键鼠。
5. 有有效dump后再决定是否需要安装[微软 WinDbg](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/)进行离线分析；官方也提供 winget install Microsoft.WinDbg。若必须人工安装，由用户完成提示。直接安装/Store版本可能自动更新，提前说明；不把它设为系统默认调试器。
6. 符号缓存只放G盘并按调试会话设置，不写全局环境；[微软符号服务器说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/using-a-symbol-server)。只请求调试符号，不上传转储。匹配的Godot私有/原生符号是否可获得仍待核实；不足时明确分析边界，未经单独批准不为符号替换或重编引擎。
