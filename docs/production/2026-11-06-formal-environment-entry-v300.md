# v300 · 正式阀门专项接入严格无窗口入口

推进 P03/Q05，未改游戏生产逻辑。`RunFormalEnvironmentInteractionTests` 是现存的独立专项；普通 `keyboard` 不会运行该入口，也不能替 v298 改绑与未绑定断言作证。现在手动 `-Phase formal-environment-interaction -SourceRows 1901` 接入标准宿主，沿用既有原时限、拥有进程、独立档位、源码／二进制／帮助器／用户保护与原始日志。精确参数禁止录制、可见窗口、诊断旗标和失败豁免；不是定时任务。

新宿主只接受 stdout 与 Godot 外部日志各一组、按顺序出现的四条记录：中英改绑／未绑定／恢复同一候选，原阀门行为完成，终结器观察，退出清理。诊断原文、缺失或重复的标记及相位混入均拒绝。离线控制先观察到 `FORMAL_ENVIRONMENT_VALIDATOR_NOT_REGISTERED`，补接后 1 正／12 反通过；另执行实际宿主的混合录制旗标反例，验证在创建测试目录前拒绝。九个专用源路径都存在且在 v294 的受保护源清单内；本轮没有尝试实际构建。

现有测试的开局等待是有限的输入采样，并非明确等 `Playing`；低资源机器若在首次卡片断言前失败，先查实际开始状态，不能误记为改键失败。本轮没有预先调整原夹具节奏。v297 的完整方向模型应使用 `RunUiConsistencyTests --phase=models` 或完整 UI 模型调用；`RunStableClawPullTests --phase=models` 只测机械爪模型，不替教学签收。雾上像素仍为单独的有显示条件验证，未启动。

当前可用内存样本约 130–319 MiB、仍有高频换页；两条旧 Godot 进程记录同时显示零线程和零句柄，不能据名称称新 KNIGHT 仍运行。没有结束其他程序、打开窗口、写真实存档或恢复自动化。资源恢复后优先单次原时限构建裂隙，按当前同一产物顺序复验冰墙／入口／教学／正式阀门；不以旧二进制跨代签收。
