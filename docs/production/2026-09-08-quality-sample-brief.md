# 序章品质样板：阶段约定

确认日期：2026-09-08。状态：用户“设立目标并进行”已批准执行盆地小循环；视觉方向与实际样板品质尚待评审。

## 已确认的目的

先制作一个面向 PC、首次正常游玩目标约 5–8 分钟的品质样板，验证《无名钟楼》能否把
机械爪移动、可读战斗、探索收益以及统一视听表现组成一段值得继续玩的体验。
以用户提供的《空洞骑士》介绍视频为完成度参考，不复制其角色、画面、地图或全作体量。
约 2–4 周是资源就绪后的验证窗口；暂停、额度、返工或资源缺口须明示，不把时间到期当作质量达标。

当前约 15–25 分钟完整序章只是后续估算范围，不在样板阶段扩建完成。
用户允许重新评估游戏内所有设计，不等于全部推倒重做，也不等于批准新的外部支出和发布。

## 事实、推理与风险

- 事实：已有五区连续序章、机械爪、一次附着助推、检查点与 Boss／结算，以及自动回归基础。
  当前仍有程序化原型观感、动作／敌人重叠、镜头接缝裁切、教学噪声与真人验证缺口。
- 推理：先统一小段体验的制作标准，能检验资产生产方式、核心玩法和实际产能，再决定是否扩大生产。
- 风险：仅靠增加代码、素材数量或后台运行时长，可能继续扩大一个没有获用户认可的原型。
  外部美术／动画协作尚未落实，不能把含该条件的 4–8 个月估算写成现有团队的承诺。

## 样板的最小范围

1. 一个有明确地标、前后层次与安全落脚面的代表性连续空间，可包含相互连通的小段，不预设必须新增扇区。
2. 一场能辨认起手、攻击范围和恢复机会的战斗；先复用现有敌人，不以新增 Boss 或复杂连招充数。
3. 一次具有实际路线收益的机械爪探索，包含抓取、牵引／助推、松手和安全返回。
4. 一项玩家可理解的奖励或捷径收益，并形成返回主路线的闭环。
5. 与这段体验配套的角色／敌人动作、场景、UI、声音与失败恢复。不能仅交一张精美静帧。

5–8 分钟是待测的首次玩家体验假设，不能靠延长走路、重复战斗或强制等待凑时长。
自动驾驶录像的几十秒通关时间也不能直接用于判断真人内容长度。

## 已批准执行的样板范围

本阶段只精修现有盆地右半部：营地／检查点 → 一场劳动者遭遇 → 抓平台底面上返补给台 → 探索补给 → 返回营地。
这一处可同时检验动作、读招、机械爪、空间层次、奖励与 UI，复用既有碰撞、存档和补给，不同时制作新 Boss 或整段上升。

另外两种路线是精修入口首敌（更低压力，但机械爪探索收益不完整），或把入口、下降和盆地合成样板（覆盖广，但首批资产和教学范围明显扩大）。
建议先验证盆地小循环；选择依据是能在同一空间检验完整体验，不是认为现有地形已经足够好。

首个运行验证必须用普通玩家入口串起整圈。旧测试分别证明了敌人接战、抓爪返台和补给，
没有证明新玩家从营地左侧接敌、防反后自行发现高台的全流程。不得手动扣血来制造奖励价值；满血玩家应保留补给而非被迫受伤。
还需检查左侧其他敌人是否造成无设计的夹击，以及新美术是否妨碍现有台下净空、威胁轮廓和关键落点。
缩小样板路线不等于修好了盆地右侧接缝镜头，旧缺陷仍须明确记录。

## 制作顺序及评审节点

| 阶段 | 产出 | 进入下一步的条件 |
| --- | --- | --- |
| 范围设计 | 根据当前地图提出一条样板路线、学习顺序、收益与失败回退 | 具体方案获用户确认；明确复用和重做部分 |
| 最小体验 | 可操作的空间与一次完整战斗／探索／奖励循环 | 无严重阻塞；先验证玩法用途，不扩大整关 |
| 运行视觉样板 | 实际引擎中的一组统一角色、敌人、环境、动作和声音 | 用户审看正常运行结果；未认可的方向不批量生产 |
| 完整样板 | 全段视听一致、恢复与引导完整、可正常启动 | 相关回归、普通窗口路线、短录像审查与交付检查通过 |
| 真人评审 | 用户体验记录与经授权招募的新玩家观察 | 根据问题决定继续、删减或重设计，再重估整关工期 |

首批建议 10–15 名未接触项目的玩家，仅用于发现理解和游玩问题；目前未招募，样本状态是“未验证”，不是 0 人通过。
招募、记录方式和任何数据上传须先另获确认；避免收集与评审无关的个人信息。

## 验收口径

- 技术：普通新局可启动；相关输入、合法／禁抓、助推／冲刺边界、能量与护盾、死亡恢复、回路与退出可重复验证。
  无需安装开发 SDK 的独立可运行包是交付目标，不把当前本机源码启动器写成已经完成的独立包。
- 画面：审看实际运行，角色与威胁可分辨，重要落点可见，UI 不遮关键交互；统一轮廓、色彩与层次由用户确认。
- 动作与声音：动作起手／执行／结束清楚，连贯且有力度；不能用名字包含 Formal、动作数量或 WAV 数量代替感官验收。
- 上手：观察未被口头讲解的玩家在哪里停住、误用技能或看不懂受伤原因，区分新玩家学习问题和机制缺陷。
- 探索：记录玩家是否发现可抓地形、是否理解收益、能否返回主线，以及是否主动再探索。
- 长度：记录真实首次游玩时长和失败分布；不人为把每位玩家固定到 5–8 分钟，也不拿代理路线作真人样本。
- 性能：注明设备、分辨率、运行方式和帧时间来源；固定帧录像和进程回调采样不能当作 GPU 性能认证。
- 完成：技术通过、用户认可和新玩家观察分别记账。缺少后两者时只叫技术／体验候选，不能标“达到参考品质”。
