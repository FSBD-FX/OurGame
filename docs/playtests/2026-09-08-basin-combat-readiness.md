# 盆地样板：按真实可用状态给出操作提示

日期：2026-09-08。基线：`90b7696eab299e60298fa8c6f7530f7d06890c0c`。这是有界教学修正，不是新发行版或整体品质验收。

## 事实、推理与风险

- 原样板教学主要读取敌人阶段。盾过热或气力耗尽时仍要求举盾，开甲时也可能向空插槽、持续举盾或不足攻击气力的玩家推荐直接攻击。
- 实际规则是攻击需要可用的1号武器、攻击气力和松开有效护盾；机械爪则在右键仍按住时不能发出，即使盾因过热已关闭。只看画面上有没有盾无法判断爪是否可用。
- 因此本次让同一教学卡读取真实输入、气力和护盾，不增加新卡片或改变操作规则。提示准确是技术条件；是否明显改善新玩家理解仍需真人观察，不能用自动测试替代。

## 实现边界

- `PlayerActionModeController.CanAffordAttack` 仅公开已有攻击准入的只读气力判断，不另造或更改消耗阈值。
- `BasinSampleGuideController` 在战斗步骤按当前真实状态覆盖标题、键位、正文：不可用护盾时避让；空插槽时先选1；有效盾仍举着时先松盾；气力不足时保持距离恢复；仍按右键阻挡机械爪时先松右键再重新发爪。
- 威胁和恢复提示只在右键实际按住时要求松开。盾耗尽关闭后继续按着右键，会再次消耗刚恢复的少量气力，这时仍须明确要求松右键；仅凭 `Shield.IsActive` 判断不够。
- 状态恢复后回到当前敌人阶段的原教学。敌人背侧状态/生命条、卡片收放、地图、碰撞、数值、时序、音频、存档及默认整关 UI 不变。
- 未生成或采购新美术，不修改旧相机草稿、导入噪声或音频总线。

## 失败证据与审查修正

证据根：`E:/OurGame/Knight/.evidence/september08-basin-readiness`。

- 首次有效 RED：`overheat-red.log`、`energy-red.log`、`shield-red.log`、`slot-red.log`、`claw-red.log`；分别复现不可用盾、负担不起攻击、缺松盾操作、缺有效插槽指引、缺按住右键阻挡爪的说明。初始构建成功，五项均为实际断言失败。
- 独立审查指出“已经松开仍要求松开”。`release-prefix-red.log` 复现过热时陈旧右键指令；改为按实际 held 状态显示。`energy-prefix-red.log` 另锁定双键已松开的低气力情况。
- 首次把低气力键位全部改为中性恢复文字后，审查发现持续按盾会耗掉恢复量。新增 `energy_held`：先通过控制器合法消耗至低气力，再由实际输入举盾自然耗尽。第一次 `held-energy-red.log` 误读了上一帧 Guide 而假绿；加两次物理/处理帧等待后，`held-energy-synced-red.log` 才有效复现缺少松盾指令。随后仅在真实 held RMB 时恢复该前缀。
- 最终专项8个场景：`overheat`、`depleted`、`energy`、`energy_held`、`shield`、`slot`、`claw`、`claw_hot`。涵盖实际 Telegraph/Attack、过热与零气力的区别、盾关闭但右键仍按着、状态恢复清除、按指示松盾后实际发动攻击、选1恢复攻击，以及过热后爪的输入门槛。
- 中文和英文1.25倍UI均检查警告显示期间的标题/键位字体宽度及可见正文卡片边界，不只检查恢复后的文本。
- 专项中的开甲及气力支出有明确受控夹具，不当成自然试玩。`BasinQualitySampleLoopProbe --overheat-approach` 则只用正常 Start 和引擎输入，先在营地举盾至过热、走近起手、松盾避让回营，再恢复并完成原整圈；不写位置、速度、生命或敌人状态。默认无该参数的路线不变。
