# 盆地样板：局部战斗状态与教学减量

日期：2026-09-08。基线：`f0cfe73178e92b64a1a0c9c456c9c380a48d25d9`。本地开发增量，不是新发行版本或最终品质验收。

## 事实、判断与边界

- 原教学把 Telegraph 与 Attack 合写成“横扫将至”，Recover 则回到普通说明；真实规则是 Recover 仍有护甲，仅 Exposed 打开生命伤害接收。这个区别应直接告诉玩家。
- 实际截图显示近身交战与长教学卡相距较远。本轮在敌人背侧给出短状态和真实生命细条；在局部信息完整可见的 Telegraph / Attack / Exposed 阶段，把左卡从168px收为100px，保留标题与键位。它是减少视线往返的候选方案，还没有真人辨认速度数据。
- 不改角色、敌人、地图、碰撞、护甲、攻击/破甲时序、伤害、气力、过热、机械爪、音频或存档。仅样板 Guide 接入新UI，默认整关不挂载；没有新付费、图像生成或素材采购。

## 实现

- `SampleGuide/View/CombatReadout` 是可独立替换的只读显示：每次从实际 actor state 和 Health 读值，不从按键次数推算伤害，不伪造破甲倒计时。
- 文本与颜色共同区分“横扫蓄力”“横扫中”“收招 · 仍有甲”“开甲”“有甲”；状态条在 Idle / Dead / 无效或隐藏对象时不显示。
- 180×30px面板位于真实朝向的背侧110px、角色上方90px，4px生命条留在面板内部。目的是留出正面的真实横扫轮廓，不改该轮廓来适应UI。
- 不把出屏提示硬夹到另一个对象上。完整面板必须在视口内且不碰教学卡，否则隐藏局部条并保留完整教学。暂停、标题、死亡、新局/恢复由原会话生命周期清除。
- 教学新增实际横扫与收招分支。英文蓄力键位保留“RELEASE AFTER SWEEP”，避免卡片收短后丢失松盾时机。

## 失败证据与修正

证据根：`E:/OurGame/Knight/.evidence/september08-basin-combat-readout`。

- `build-red.log` 是夹具误用不存在的 Pause/Resume 方法造成的编译失败；修正为真实 PauseMenu 接口后，`build-valid-red.log` 成功，`readout-red.log` 才是有效的缺失局部UI RED。不把夹具编译错误说成生产缺陷。
- `readout-first.log` 初版状态/生命/生命周期通过，但 `normal-first/03-telegraph.png` 暴露视觉缺陷。`geometry-red.log` 实测生命条为27px，虽然最小尺寸已经为1px；原因是默认主题/百分比设置前先设了Size。改在样式和入树完成后设置4px，随后 `anchor-red.log` 单独复现平台边缘被遮。
- 初次普通流程同时在旧正文高度断言处失败：紧急卡有意隐藏正文，测试却检查隐藏内容的几何。探针现保留可见正文包含断言；只有紧急真实阶段且局部条可见，才允许隐藏正文和100px卡。另检查实际阶段、血量、文字宽度、条高度和卡片避让；没有改输入路线来让测试通过。
- 独立审查发现仅用 Intersects 会在状态文字全部出屏、生命条仍露出时错误收短教学。`edge-red.log` 有效复现；改用 Encloses，顶部/侧面受控边界夹具均通过。
- 主代理与独立审查均看见居中条压暗横扫顶部；`rear-red.log` 先锁定背侧避让，再改为按真实 Facing 偏移。`readout-rear-final.log` 的失败来自夹具错误假设“开甲立即转向”；生产逻辑只在移动或新起手时更新朝向。修夹具为等待真实右向起手，再重新开甲继续生命/暂停检查；不修改敌人转向规则。
- 最终 `readout-release.log` GREEN：真实四阶段可见性/生命、上下及侧边几何、两种实际朝向、裁切回退、英文收招文字宽度、暂停/恢复/死亡/新局。这里包含受控放置和受控伤害夹具；与未改状态/位置的普通输入路线分别记账。
