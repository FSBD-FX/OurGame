# 《无名钟墓 / The Nameless Belfry》Steam Demo 设计规格

- 状态：已完成讨论，等待用户复核书面规格
- 日期：2026-08-12
- 项目目录：`E:\OurGame\Knight`
- 引擎：Godot 4.7.1 Mono
- 正式玩法语言：C# / .NET 9
- 首发平台：Windows PC / Steam Demo
- 首发语言：简体中文、英文
- 目标体验时长：10–15 分钟

## 1. 产品目标

制作一段可公开发布、达到 Steam Demo 展示标准的原创 2D 动作探索垂直切片。体验同时验证三根支柱：

1. 精准、顺滑且具备进阶空间的近战与移动手感。
2. 拥有分岔、隐藏空间和捷径的小型环形探索区域。
3. 中等难度的平台挑战，以及由三种能力共同完成的组合关卡。

玩家完成 Demo 后应留下三个明确印象：操作值得继续精通，遗迹值得继续探索，主角的真实身份值得继续追问。

本项目只参考《空洞骑士》对动作探索品类的节奏与完成度，不复制其角色轮廓、面具与角形设计、武器比例、世界设定、地图布局、敌人、Boss、文本、美术资产、音乐或标志性演出。项目将建立独立的黑暗童话与破败机械视觉语言。

## 2. 世界、主角与身份线

世界是一座被幽光植物与铜绿侵蚀的机械墓园。古老葬钟原本负责保存死者的“残响”，如今钟楼失控，机械守墓者逐渐被错误的记忆吞噬。

主角以失忆的发条人偶身份苏醒，使用一副被废弃的机械骑士躯壳。旅程中，他继承守墓提灯并被称为最后的守墓人；更深层真相是，机械躯壳中封存着一名无名孩童的残响意识。

首个 Demo 不制作即时变身或多躯壳切换。玩家始终操控同一角色，三重身份通过剧情、装备、能力和外观逐步显现：

- 发条骑士：机械身体、钟刃剑术与基础战斗身份。
- 提灯守墓人：守墓披肩、提灯余烬与职责的继承。
- 无名孩童：月银记忆、内心残句与后续真相伏笔。

Demo 结尾只揭示“最后的守墓人”这一层，不解释孩童为何被封存，也不揭示整个王国的历史。

## 3. Demo 旅程

Demo 采用“螺旋环形遗迹”结构，并在试炼与结尾短暂进入记忆空间。

1. **苏醒庭院**：玩家在守墓灯旁苏醒，学习移动、跳跃、劈砍、下劈与丝线牵引。
2. **断齿回廊**：遇见首个普通敌人，学习观察前摇、闪避与反击。
3. **环形分岔**：玩家在上层摆钟架和下层埋机道之间选择先后顺序。
4. **无名匣室**：可选隐藏房，展示孩童被装入机械躯壳的模糊壁画。
5. **捷径开启**：两条路线在残响祭台汇合，并开启返回苏醒庭院的捷径。
6. **残响试炼**：进入月银记忆空间，临时唤醒提灯余烬和残响齿轮。
7. **葬钟塔攀登**：使用三种能力完成短小但完整的组合挑战。
8. **堕落钟守**：Boss 战由铜绿常态转入锈红失控状态。
9. **月银余音**：钟守短暂恢复意识，称主角为最后的守墓人；临时能力消退，进入 Demo 结算页。

隐藏空间只提供世界观碎片、原画收集物或外观徽记，不提供通关所必需的数值强化。

## 4. 玩家控制与基础战斗

设计原则是立即响应、容易理解、能够精通。具体数值在灰盒手感测试中确定，不在本规格中预设未经验证的速度或帧数。

### 4.1 移动

- 快速起步与短刹车距离。
- 空中保持较强方向控制。
- 轻按低跳、长按高跳。
- 支持跳跃输入缓冲和离地宽容时间。
- 冲刺为短距离高速位移，可在空中使用一次；落地后恢复。
- 冲刺不穿透敌人，也不提供全程无敌，主要依靠空间判断躲避。

### 4.2 钟刃剑术

- 地面横斩。
- 空中横斩。
- 向上挑击。
- 空中下劈。
- 下劈命中敌人、钟体或指定机关后反弹，可衔接跳跃、冲刺和丝线。
- 命中反馈包括短暂停顿、敌我击退、音效、粒子和有限的画面震动。
- 攻击前摇、有效区间和收招必须可读；不依靠隐藏判定制造难度。

## 5. 三种能力

Demo 采用“残响试炼”结构：机械丝线为永久能力，提灯余烬与残响齿轮在试炼内临时唤醒，最终组合使用。正式游戏再逐步永久解锁后两项能力。

### 5.1 机械丝线

- 对锚点：快速牵引或摆荡。
- 对轻型敌人：将敌人拉向玩家。
- 对重型敌人与 Boss：将玩家拉近，或扯开短暂弱点。
- 对机关：扯动拉杆、钟锤和机械门。
- 使用短冷却而非魔法消耗，鼓励频繁使用。

### 5.2 提灯余烬

- 发出短距离脉冲，照出隐藏道路、铭文和敌人弱点。
- 点燃熄灭机关，使平台或机械短暂运转。
- 标记敌人后，下一次钟刃命中触发灼裂。
- 消耗余烬值；余烬通过守墓灯、试炼火盆和精准攻击补充。

### 5.3 残响齿轮

- 记录玩家最近约两秒的移动或攻击。
- 再次触发后，残响将这段动作重演一次。
- 可用于同时压住机关、制造延迟斩击、夹击敌人或重复丝线动作。
- 同一时间只允许一个残响，且不允许递归录制残响自身行为。
- 不能复制菜单、暂停、受击、死亡、场景切换或剧情交互。

### 5.4 组合范例

提灯照出隐形锚点，丝线牵引跃过断层，残响重复拉动钟锤，玩家下劈钟体反弹至高台。最终 Boss 处决同样要求残响拉钟锤与玩家下劈钟心同步完成。

键鼠与手柄为三项能力提供独立 Action，不使用暂停式轮盘。

## 6. 平台、地图与重试

主路线为中等难度，重点是流畅探索，不安排长时间连续高精度操作。高难度挑战位于隐藏路线，不阻挡通关。

地图区域：

- 苏醒庭院：安全区、第一盏守墓灯和基础教学。
- 断齿回廊：战斗与丝线教学。
- 上层摆钟架：锚点、摆荡和下劈反弹为主。
- 下层埋机道：战斗密度更高、空间更窄、补给更多。
- 无名匣室：隐藏叙事房间。
- 残响祭台：捷径与能力试炼入口。
- 葬钟塔：三能力组合攀登和 Boss 房。

死亡后在最近的守墓灯复活，不损失永久资源，普通敌人与机关重置。平台坠落优先执行短距离安全点重置；Boss 失败从门外守墓灯立即重试，不要求重新跑图。

## 7. 敌人与 Boss

### 7.1 普通敌人

- **锈壳侍从**：基础近战敌人，慢速挥砍，可被丝线拉动。
- **墓灯蛾**：空中骚扰敌人，会追逐光源，可用提灯改变其位置。
- **背钟苦役**：重型敌人，正面防御高；丝线可扯开背部钟罩，下劈也能创造机会。

每种敌人只承担一个主要教学职责。首个 Demo 不增加仅靠换色和数值变化形成的新敌人。

### 7.2 堕落钟守

Boss 是一名被葬钟残响侵蚀的巨型守墓机械，轮廓与攻击均围绕钟锤和胸口钟心构成。

**第一阶段：**

- 钟锤横扫。
- 跃击。
- 地面震波。
- 节奏强调观察、跳跃、拉开距离与短窗口反击。

**转阶段：**

- 生命降至约 60% 时敲响葬钟。
- 视觉从铜绿梦墓切换为锈红葬钟。
- 部分平台开始移动，场景落下火星与机械碎屑。
- 转阶段演出不造成无预警伤害。

**第二阶段：**

- 增加钟声冲击、钟锤牵引与连续跃击。
- 玩家可用丝线打断钟锤，用提灯照出胸口钟心。
- Boss 不通过单纯提高血量延长战斗。

**最终处决：**

- 玩家录制一次拉动钟锤的动作。
- 残响重演拉动动作时，玩家下劈暴露的钟心。
- 处决由玩家实际完成，不替换为不可交互播片。

Boss 失败可立即重试。关键攻击同时具备动作、音效和地面/空间提示，不只依赖颜色。

## 8. 视觉语言

正式制作采用手绘分层角色、骨骼动画和少量关键逐帧修形。攻击、受击、处决与 Boss 关键动作使用逐帧特效增强冲击。背景采用分层绘景、视差、2D 灯光、局部雾和粒子。

### 8.1 三种情绪状态

- **C：铜绿梦墓**是常态。铜绿机械、骨白陶瓷、幽光植物与潮湿薄雾构成主要世界。
- **B：锈红葬钟**表示高压、失控与部分 Boss 状态。使用锈红炉光、火星和强阴影。
- **A：月银哀歌**表示寂静、记忆和身份揭示。使用低饱和银蓝、漂浮尘埃和近乎静止的背景。

三种状态共享相同的角色造型、材质规则、环境构件和轮廓语言，只改变光色、粒子密度、背景运动和音乐层次，避免产生三个不同游戏的割裂感。未来不同旅程与 Boss 可使用不同配比，但不能破坏统一规则。

### 8.2 主角轮廓

主角由骨白陶瓷外壳、铜制关节、机械丝线盘、破旧守墓披肩和提灯构成。造型避免昆虫面具、角状头饰、细长骨钉武器及其他容易与参考作品混淆的标志性比例。

## 9. 音频

- 铜绿区域：机械摩擦、滴水、远处钟声和低沉弦乐。
- 月银空间：弱化节拍，突出音乐盒、呼吸般童声质感和反向钟音。
- Boss 第二阶段：工业打击乐和失真钟鸣，攻击提示音保持独立、清晰。
- 丝线、提灯与残响各自拥有稳定且可辨识的声音主题。
- 命中、受击、招架窗口和能力成功都不能只依赖视觉反馈。

设置中分别提供主音量、音乐、音效和环境音控制。

## 10. 叙事与本地化

叙事以环境为主，辅以少量 NPC 残响对白与极短的主角内心残句。

- “无火执灯者”的残响负责提供少量引导，不承担大段世界观说明。
- 壁画、损坏铭牌、敌人姿态和场景构图传递主要背景。
- Demo 正文控制在约 800–1200 个中文字的等量内容，以确保简中和英文均能精修。
- 所有文本使用稳定文本键管理，不把可见文案直接写入场景或玩法脚本。
- 字体与布局必须覆盖中英文字符，并测试长英文文本的换行和溢出。
- 结尾对白只确认“最后的守墓人”身份。

## 11. UI、输入与可访问性

HUD 保持克制：左上显示生命、余烬值和临时能力状态；Boss 战显示钟心状态。非必要界面在探索时淡出。

首版支持：

- 键鼠和 Xbox、PlayStation 风格手柄完成全部操作。
- 输入设备切换后自动更新提示图标。
- 自定义按键并检测关键 Action 未绑定或冲突。
- 窗口、无边框和全屏模式。
- 常用分辨率与 UI 缩放适配。
- 主音量、音乐、音效、环境音控制。
- 手柄震动强度、屏幕震动强度和闪光削弱。
- 色彩辅助和字幕大小。
- 暂停菜单中的能力说明、当前目标、设置、返回守墓灯和安全退出。

核心提示同时使用形状、动画、声音和文字，不只依赖颜色。

## 12. 技术架构

### 12.1 技术边界

- 正式玩法使用 Godot 4.7.1 Mono、C# 和 .NET 9。
- 现有编辑器插件可保留 GDScript；核心玩法不在 C# 与 GDScript 之间随意拆分。
- Godot AI 只用于开发，不进入发布包。
- Beehave 保留为可选工具。首版普通敌人与 Boss 优先使用简单、可测试的有限状态机，不为了使用插件强行引入行为树。
- Steamworks 通过独立平台服务接口接入；Steam 未运行时，游戏仍可启动、存档和完成 Demo。

### 12.2 模块划分

- `PlayerMotor`：地面、空中、跳跃、冲刺与碰撞响应。
- `PlayerCombat`：攻击请求、连贯动作、命中与受击窗口。
- `HealthComponent`：生命、无敌窗口、死亡与信号。
- `AbilityController`：能力输入、装备状态和公共冷却协调。
- `ThreadAbility`、`EmberAbility`、`EchoAbility`：三项能力的独立实现。
- `PlayerAnimationCoordinator`：把玩法状态映射到动画，不反向持有玩法规则。
- `EnemyStateMachine`：普通敌人的可读有限状态机。
- `FallenBellkeeperController`：Boss 阶段、攻击选择和处决条件。
- `CheckpointService`：守墓灯、短距离安全点和复活。
- `SaveService`：版本化存档、备份和恢复。
- `LocalizationService`：文本键、语言切换和缺失键诊断。
- `PlatformService`：Steam 与本地回退实现。

模块通过信号、事件或小型接口协作。玩家输入只读取 Godot InputMap Action，玩法类不写死物理按键。

### 12.3 核心数据流

输入 Action 进入玩家控制器；控制器根据当前状态把请求交给移动、战斗或能力组件；组件修改物理状态或生成明确的命中/交互请求；目标组件处理伤害、牵引或机关变化；动画、音频、特效和 UI 监听结果事件并呈现反馈。表现层不能直接决定伤害、冷却或通关状态。

场景切换和守墓灯激活产生保存请求。`SaveService` 先生成版本化数据快照，写入临时文件，验证可读后替换正式文件，并保留上一份有效备份。

## 13. 错误处理与恢复

- 存档读取失败：保留损坏文件，提示尝试备份或创建新档，不静默覆盖。
- 存档写入失败：保持上一份有效存档，并在非战斗时显示可理解提示。
- 输入设备断开：游戏自动暂停并允许切换键鼠或重新连接手柄。
- 文本键缺失：开发构建显示醒目标记并记录键名；发布构建回退英文且记录诊断。
- 音频或装饰资源缺失：不阻断玩法；关键碰撞、场景或脚本缺失则停止进入该场景并显示恢复选项。
- Steam 接口不可用：回退本地平台服务，不阻止启动和结算。
- 玩家卡入地形：使用最近安全点恢复；Boss 战恢复到门外守墓灯。
- 残响录制遇到非法状态：终止本次录制并安全清除残响，不复制死亡或场景切换。

## 14. 存档模型

Demo 使用一个自动存档槽，设置数据单独保存。进度档保存：

- 存档格式版本。
- 最近守墓灯。
- 已开启捷径。
- 已发现收集物与隐藏房。
- 已完成教程提示。
- 残响试炼当前阶段。
- 必需的剧情标记。

语言、音量、显示、输入和可访问性设置保存在设置文件。试炼临时能力只在剧情允许的区域保持；离开试炼或完成 Demo 后按剧情回收。存档目录与文件名保持稳定，为后续 Steam Cloud 预留。

## 15. 测试与验收

### 15.1 自动化验证

- C# 编译和 Godot 资源导入无错误。
- 移动状态、跳跃缓冲、离地宽容和空中冲刺恢复。
- 伤害、无敌窗口、命中与死亡流程。
- 三项能力的冷却、资源、目标筛选和非法状态保护。
- 残响记录与重演的确定性边界。
- 存档写入、备份、损坏恢复和版本升级。
- 中英文文本键完整性、字体覆盖和基础溢出检测。
- 键鼠与手柄的必需 Action 映射。
- 从新游戏到结算页的无阻断冒烟流程。

### 15.2 手工验证

- Windows 10 和 Windows 11 x64。
- 键鼠、Xbox 风格手柄和 PlayStation 风格手柄。
- 1080p 及常见 16:9 分辨率，窗口、无边框和全屏。
- 手柄中途断开、切换输入设备和重新绑定按键。
- Boss 各阶段、转阶段、处决、死亡重试和暂停恢复。
- 简体中文与英文的教程、对白、设置、暂停和结算页面。
- 闪光削弱、震动、屏幕震动、字幕和色彩辅助设置。

## 16. Steam Demo 完成标准

- Windows 10/11 x64 可独立安装、启动、完成和卸载。
- 以 GTX 1060 / RX 580、四核 CPU、8GB 内存为参考，在 1080p 下目标稳定 60 FPS。
- 未接受开发者口头指导的新玩家能够在 10–15 分钟内完成 Demo。
- 简体中文和英文无缺失、乱码和阻断阅读的溢出。

## 17. 里程碑与范围边界

实施分为五个里程碑：

1. **技术原型**：移动、近战、丝线和单一测试敌人，全部使用临时表现。
2. **灰盒完整流程**：环形地图、三敌人、临时能力、Boss 与结算可从头到尾完成。
3. **正式美术与音频**：替换角色、场景、动画、特效、声音和音乐。
4. **内容与双语打磨**：叙事、UI、设置、可访问性、中英文和教学。
5. **Steam 发布候选版**：性能、兼容性、安装包、Steamworks、回归测试和公开发布材料。

首个 Demo 明确不包含：完整世界地图、多区域长期流程、即时身份变身、多武器系统、技能树、装备数值构筑、复杂经济、多周目、在线功能、多人模式、完整成就集、Steam Cloud 正式启用或超出一场 Boss 的内容扩张。这些内容只有在 Demo 核心体验验证成功后再评估。
