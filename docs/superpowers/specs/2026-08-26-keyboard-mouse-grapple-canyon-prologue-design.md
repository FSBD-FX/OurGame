# 键鼠战斗、机械爪与 U 型峡谷序章设计

**日期：** 2026-08-26

**状态：** 2026-08-29 机械爪、密闭多层地图与内容密度修订版已获用户批准

**工程：** Godot 4.7.1 Mono / C# / 2D 横版动作游戏

## 1. 背景

当前序章使用 `J` 攻击、`K` 机械丝、方向键瞄准和六个独立房间切换。机械丝对预先放置的目标施加一次离散牵引，并带有 0.35 秒冷却。该结构已经具备敌人、机关、检查点、Boss、UI、音频、动作和证据门禁，但不能满足新的键鼠操作、连续机械爪移动和 U 型峡谷空间体验。

本轮改造把键盘用于移动与模式／装备选择，把鼠标用于指向、执行攻击、发射机械爪和展开护盾。首关改为一套连续世界坐标下的无缝 U 型峡谷：从左侧高处下降，在谷底向右前进，从右侧攀升，再向右进入遗落机械神殿。复杂度来自空间层次、材质判读、回望路径、机关和短支路，不来自二段跳、隐藏组合键或像素级操作。

## 2. 目标

1. 建立清楚、无歧义的键盘移动＋鼠标战斗操作。
2. 用 `Q` 和 `E` 分别选择攻击模式与机械爪模式，左键执行当前模式。
3. 用右键展开具有能量消耗和过热限制的披风能量盾。
4. 建立 `1–4` 四个装备槽；第一关只实装 `1` 号近战武器，其他槽位保留完整接口。
5. 将机械丝改造成可直接抓取墙壁、天花板、平台底部和边缘，可摆荡、收放绳、锁定跃升，并继续作用于敌人和机关的机械爪。
6. 用明确的表面材质区分可抓岩壁／金属、专用锚点、冰面和禁抓区域。
7. 把现有房间式首关改造成视觉和操作连续的无缝分区世界。
8. 保持角色、地图、UI、特效和音频的稳定替换接口，玩法验收完成前不启动正式美术制作。
9. 继续满足 0 警告／0 错误、完整验证、性能、录像、关键帧和正常速度真人试玩门禁。

## 3. 非目标

- 本轮不制作或购买正式角色、场景、敌人、Boss 或 UI 美术。
- 本轮不实装远程武器、消耗品或 `2–4` 号槽位内容。
- 本轮不增加二段跳，不把空中冲刺设为主线必需能力。
- 本轮不制作序章以外的关卡。
- 本轮不以自动路线的时间替代正常速度真人试玩。
- 本轮不移除手柄兼容层，但键盘鼠标是第一关的主要设计与验收输入。

## 4. 输入与模式

### 4.1 基础输入

| 输入 | 行为 |
| --- | --- |
| `A / D` | 水平移动 |
| `W / S` | 机械爪连接时收绳／放绳；其他情境保留给向上交互与向下穿越平台 |
| `Space` | 未连接时执行单次普通跳跃；机械爪连接时保持绳索并触发每次锁定至多一次的摆荡跃升 |
| `Shift` | 地面或每次腾空一次的方向冲刺；主线不依赖它 |
| `Q` | 持续选择攻击模式，直到下一次模式切换 |
| `E` | 持续选择机械爪模式，直到下一次模式切换 |
| 左键 | 执行当前 `Q / E` 模式 |
| 按住右键 | 朝向鼠标展开披风能量盾 |
| `1–4` | 选择装备槽 |
| `Escape` | 暂停 |

鼠标位置转换为世界坐标，并成为攻击方向、机械爪目标和护盾朝向的唯一键鼠瞄准源。攻击方向在现有横向、向上、向下动作集合内按鼠标方向解析；不得继续从 `W / S` 推断攻击方向。

### 4.2 模式与装备槽

`Q / E` 是动作模式，不占用装备槽。`1–4` 是装备选择，不改变动作模式。第一关开始时默认选择攻击模式和 `1` 号近战武器。

- `1` 号槽：现有近战武器，可执行攻击。
- `2–4` 号槽：可选择的空槽，显示明确空状态；左键攻击请求被拒绝并给出反馈。
- `E` 模式不依赖当前装备槽，机械爪始终可用。
- 以后加入远程武器时，数字键选择武器，`Q` 选择攻击模式，左键朝鼠标使用该武器。

### 4.3 动作仲裁

- 举盾时不能开始攻击或发射新的机械爪。
- 已经锁定的机械爪在举盾时保持连接，但暂停 `W / S` 收放绳和空格跃升；角色仍随现有惯性摆动。
- 机械爪连接时按 `Q` 会安全收回抓手并切换到攻击模式。
- 攻击动作已经进入有效阶段时，`E` 只更新下一动作模式，不截断命中帧。
- 受到伤害、死亡、复活、暂停返回检查点或关卡卸载时，攻击、护盾和机械爪瞬态统一清理。
- 模式、槽位、能量不足、过热和机械爪失败都必须有不同的可见与可听反馈。

## 5. 能量、攻击与护盾

### 5.1 统一能量

角色拥有 100 点能量。首轮正式调校值如下，并集中存放在可验证的 tuning resource 中：

- 成功开始一次近战攻击消耗 12 点能量。
- 能量不足时攻击不开始，也不进入假动作或消耗命中 ID。
- 最后一次能量消耗结束 0.55 秒后，以每秒 28 点恢复。
- 机械爪不消耗能量。
- 死亡或检查点恢复时能量回满。

### 5.2 披风能量盾

按住右键时，护盾朝向鼠标，覆盖角色正面的 150 度扇区。举盾期间移动速度降低 35%。

- 护盾持续消耗每秒 24 点能量。
- 护盾持续增加每秒 42 点热量。
- 松开护盾 0.35 秒后，热量以每秒 35 点下降。
- 热量达到 100 时强制关闭并进入过热状态。
- 过热状态在热量降到 35 以下时解除。
- 能量归零时护盾立即关闭，但不会触发额外过热；当前热量照常冷却。
- 过热期间可以移动、攻击和使用机械爪，只不能再次展开护盾。

伤害请求增加稳定的防御分类：`Normal`、`Heavy`、`Unblockable`。

- 正面 `Normal` 攻击完全格挡，仍产生接触反馈并保留该攻击的唯一身份，不能同一攻击重复结算。
- 正面 `Heavy` 攻击额外消耗 24 点能量，仍造成 1 点伤害，击退缩小到原值的 45%。能量不足以支付额外消耗时，护盾破开并按未格挡重击结算。
- `Unblockable` 攻击不受护盾影响，但必须使用区别于普通／重击的明确预警。第一关主线不依赖玩家第一次见到不可格挡攻击就立即反应。
- 来自身后的攻击不被护盾格挡。

## 6. 机械爪

### 6.1 生命周期

机械爪使用显式状态：`Idle → Aim → Windup → Travel → Latched → Reel/Swing/Boost → Released/Retract → Idle`，失败进入带原因的短暂 `Failed` 状态。最大基础距离为 620 像素，主线必要抓点保持在 360–520 像素范围。它没有传统冷却，但一枚抓手完全收回前不能再次发射。

在 `E` 模式中，鼠标指向目标并按下左键发射；按住左键维持连接；`A / D` 调整摆动；`W / S` 收绳或放绳；松开左键断开并保留切线惯性。连接时按 `Space` 不断绳，而是叠加一次向上与当前摆荡切线混合的跃升速度；每次锁定只接受一次，落地或重新锁定后恢复资格，不能借此形成无穷空中攀升。该动作是依赖有效绳索的机械爪跃升，不是脱离机械爪也能使用的二段跳。

抓手连接使用持续绳长约束与柔和牵引，不再只施加一次离散速度。发射中的再次按压不会暗中部署第二枚抓手；玩家松开左键完成收回后才能重新选点发射。

主线专用锚点提供 36 像素鼠标吸附容差。普通地形使用鼠标到世界坐标的视线射线命中点，不把整块墙体吸附到预设中心。主线落点只允许轻度速度修正，不得传送角色，也不得把明显失败强制改为成功。

### 6.2 表面材质

抓取解析采用“地形射线＋类型化表面＋专用锚点”的混合结构：

1. 鼠标准星从玩家发出世界碰撞射线，只查询 gameplay 抓取层并要求无遮挡视线。
2. 射线可以命中地形碰撞形状上的任意有效点，因此墙壁、天花板、平台底部和平台边缘均可成为真实抓点。
3. 命中碰撞体通过 `GrappleSurface2D`、稳定的碰撞所有者元数据或等价资源取得材质；视觉节点不参与玩法判定。
4. `DedicatedAnchor` 仍作为教学、关键机关和高可靠主线点，拥有有限的准星吸附与更强反馈。
5. 过短绳长、越界、被前景 gameplay 遮挡、目标卸载和非法法线均拒绝锁定，不能穿墙或抓住纯装饰。

| 材质 | 结果 |
| --- | --- |
| `GripStone` | 粗糙峡谷岩壁，可抓 |
| `TempleMetal` | 神殿承重金属，可抓 |
| `DedicatedAnchor` | 主线教学和高可靠抓取点，可抓并带更强提示 |
| `Ice` | 不可抓；爪头明显滑脱，播放冰屑／火花和短促音效 |
| `Forbidden` | 不可抓；用于远景、薄装饰、脆弱边缘和关卡边界，不显示虚假可抓提示 |

机械爪目标解析必须区分超出距离、视线遮挡、冰面打滑、禁抓区域、目标失效、抓手未收回和无目标。失败不消耗能量。

### 6.3 敌人和机关

现有机械丝语义通过适配层保留：

- 抓世界表面或专用锚点：牵引玩家并建立绳索。
- 抓轻型敌人：把敌人拉向玩家，不把玩家锁入持续绳索。
- 抓重型敌人的指定部件：触发弱点暴露，不拖动敌人主体。
- 抓机关：拉动对应机构。

敌人、机关和世界表面共用目标查询与失败反馈，但各自的施加行为仍由独立 receiver 接口拥有。

## 7. 连续 U 型峡谷

### 7.1 无缝分区架构

首关运行在一个连续世界坐标中。玩家、HUD、进度、音频和镜头常驻；入口、下降段、谷底、攀升段和神殿是独立子场景，但不存在黑屏、房间传送或玩家重新定位。

`SeamlessPrologueWorld` 保持当前分区及其前后相邻分区处于准备状态，并按有界策略释放远离玩家的分区。关键锚点、检查点、Boss 门和连续绳索段不得跨越分区加载边界。镜头限制在经过短距离混合后切换，不得跳变。

### 7.2 主线路线

连续五分区进一步拆分为约十五个不经传送的微场景；复杂度来自空间回环、机关、战斗、可选探索和环境叙事，而不是更窄的容错窗口。

1. **峡谷入口：** 断桥瞭望台、悬吊货场和坍塌门廊。从左侧高处出发，教学移动、跳跃、`Q`、左键攻击、攻击能量和一次低风险墙面抓取。玩家能提前看见稍后打开的返回捷径。
2. **折返下降井：** 起重机竖井、冰霜通风道、破损升降梯和隐藏档案侧室。路线以左右折返的墙面、天花板横梁和承接平台教学抓墙、抓顶摆荡、空格锁定跃升、`W / S` 收放绳与冰面拒绝；不再使用一整屏无结构深坑。
3. **谷底机械遗迹：** 齿轮坟场、蒸汽泵房、积水维修渠、检查点营地和可选废料收藏室。玩家向右穿过倒塌机械、断桥和配重机关，教学右键护盾、热量和恢复，并激活第一个正式检查点。
4. **右侧多层攀升架：** 配重井、脚手架回廊、钟摆厅、天花板运输轨道和可选高处遗迹。三组由易到难的辅助摆荡交替使用墙面、平台底部、天花板与专用锚点；失误落到邻近承接层并可重新攀回，不要求空中冲刺。
5. **遗落机械神殿：** 外墙封印、守卫工坊、钟殿前厅、第二检查点、Boss 大殿和战后出口。综合使用攻击、机械爪、护盾与机关抓取；神殿入口提供 Boss 快速重试，战后灯光和机械状态形成明确变化。

机械爪在主线中承担四种可辨认职责：必需但低难度的移动、坠落时抓近处表面自救、拉动配重／平台／暗门／钟体、拉动轻型敌人或触发重型敌人的指定部件。每项职责先单独出现，再重复一次，最后才与另一项规则组合。

现有 Fallen Bellkeeper 保留为第一关 Boss，但空间和叙事身份调整为峡谷神殿守卫。神殿内部捷径开启后，从神殿入口可快速返回 Boss 前厅。

### 7.3 可选内容和难度约束

- 谷底包含一个短隐藏补给洞。
- 攀升顶部包含一个短高处机械遗迹。
- 可选区域只奖励恢复或世界信息，不影响主线完成。
- 主路线、失败承接路线、短回环与可选侧室在空间上可互相看见，但用灯光、轮廓和活动机械持续指明主方向。
- 关键落脚平台宽度不小于约 180 像素；教学落差下方至少有一层近距离承接平台，连续跌过设计好的恢复层后才进入坠落复位。
- 必要机械爪段不能被普通跳跃直接跳过，但必须允许在附近承接层重新尝试，不能一次失败退回远处。
- 主线不要求二段跳、空中冲刺、隐藏组合键、连续完美摆荡或像素级鼠标命中。
- 主线抓取点、落点和敌人必须留出适合首次玩家的反应空间。
- 坠落恢复不得把玩家推进到尚未激活的检查点。
- 必经内容目标维持正常速度首次通关约 10–15 分钟；隐藏档案、废料收藏室和高处遗迹均为可选，完整探索可以延长到约 16–20 分钟。

## 8. 检查点、复活与持久状态

第一检查点位于谷底、攀升段之前；第二检查点位于神殿入口、Boss 之前。死亡或坠落恢复时：

1. 停止当前攻击并关闭命中框。
2. 安全收回机械爪，移除绳索约束和世界标记。
3. 关闭护盾，热量清零，能量回满。
4. 清除残留敌人攻击、机械爪和护盾表现。
5. 恢复到最近已经激活的检查点；没有检查点时回到关卡起点。
6. 保留已完成教程、已开启捷径、已取得可选发现和已经确认的关卡进度。

无缝分区切换不得重置能量、热量、当前模式、装备槽、敌人进度、机关或捷径。旧版存档只迁移与世界坐标无关的设置和完成标志；旧房间坐标、入口 ID 和瞬态战斗状态不迁移。

每次坠落和死亡额外记录：世界坐标、当前分区、最后有效落脚平台 ID、当前与最近一次有效检查点、机械爪状态、抓取目标与材质、失败原因，以及死亡前短时间窗口内的输入边缘摘要。该数据只写入本地试玩报告，用于把“从门或缺口掉下去”还原到具体位置；自动测试不得伪造真人 qualitative 字段。

## 9. HUD、指导与反馈

### 9.1 稳定 UI 路径

实现需保留或建立以下稳定替换边界：

- `Hud/FormalHud/ResourceCluster/Energy`
- `Hud/FormalHud/ResourceCluster/Heat`
- `Hud/FormalHud/ModeSelector/Attack`
- `Hud/FormalHud/ModeSelector/Grapple`
- `Hud/FormalHud/Loadout/Slot1` 至 `Slot4`
- `Hud/FormalHud/AimReticle`
- `Player/VisualRoot/Shield`
- `Player/VisualRoot/MechanicalClaw`

左上显示生命、能量和热量；左下显示 `Q / E` 双模式；底部中央显示 `1–4` 装备槽；鼠标准星显示攻击方向或机械爪目标状态。过热、空槽、能量不足和抓取失败不能共用无法区分的提示。

机械爪目标至少使用四套视觉／线型语义：可抓、冰面、遮挡、超距。所有反馈同时使用形状或动画差异与声音差异，不能只依赖颜色。

### 9.2 首关限定指导

指导只在第一关第一次遇到对应机制时出现，并可通过现有首关指导开关隐藏：

1. `Q / E` 模式切换。
2. `1–4` 装备选择和空槽反馈。
3. 攻击能量消耗与恢复。
4. 右键护盾、热量和过热。
5. 可抓岩壁与不可抓冰面。
6. `A / D` 摆荡、`W / S` 收放绳、连接时空格跃升和松开左键安全脱离。

指导文本、目标标记和真实输入绑定从同一状态模型生成，不能在按键更改后保留旧 `J / K` 文案。

## 10. 美术与音频边界

每个分区提供稳定路径：

- `VisualRoot/Background`
- `VisualRoot/Midground`
- `VisualRoot/GameplayReadable`
- `VisualRoot/Foreground`
- `VisualRoot/Effects`

地形碰撞、抓取材质、敌人、机关和检查点位于 gameplay 层。正式场景美术以后替换上述 visual 子树，不得改变抓取表面、落点、敌人范围或检查点坐标。

当前阶段使用清晰的程序化占位形状与现有可替换角色／敌人表现。新增音频使用项目自有的确定性程序化资源或现有资源：模式切换、抓手发射、飞行、锁定、绳索张力、冰面滑脱、护盾展开、格挡、重击穿透、能量不足、过热和冷却完成。正式美术制作只在本规格的第一关玩法、验证和真人试玩完成后启动；任何付费生成仍需单独取得用户确认。

## 11. 组件与数据流

### 11.1 新组件

- `PlayerActionModeController`：拥有动作模式和装备槽选择。
- `PlayerEnergyModel`／`PlayerEnergyController`：拥有能量、恢复、热量和过热。
- `PlayerShieldController`：拥有盾朝向、移动缩放和防御判定。
- `MechanicalClawModel`／`MechanicalClawController`：拥有抓手状态、绳长、摆荡和施加行为。
- `GrappleSurface2D`：拥有世界表面语义与目标点。
- `SeamlessPrologueWorld`：拥有分区准备／挂载／释放、连续坐标、检查点和捷径。
- 对现有 `ThreadTarget2D` receiver 的兼容适配层：保留敌人和机关行为，移除旧冷却与一次性世界锚点牵引假设。

### 11.2 每帧数据流

1. 输入读取器采集键盘、鼠标世界坐标和动作边缘。
2. 模式控制器解析 `Q / E` 与 `1–4`，产生稳定选择状态。
3. 护盾控制器先解析右键和防御互斥状态。
4. 左键根据当前模式路由到攻击或机械爪；不能由鼠标是否碰巧指向目标来偷换模式。
5. 能量控制器只为成功接受的攻击／护盾消耗结算。
6. 移动控制器合成普通移动、冲刺、盾移动缩放和机械爪约束。
7. 表现协调器和 HUD 订阅不可变状态帧，播放视觉与音频，不回写玩法结果。

## 12. 错误处理与不变量

- 无效抓取不能产生隐形牵引、能量消耗或残留绳索。
- 分区卸载前必须解除指向该分区节点的抓手锁定，并发布明确目标失效状态。
- 任何时刻最多存在一枚玩家机械爪、一条绳索约束和一个有效抓取目标。
- 护盾不能重复处理同一个攻击身份，也不能挡住角色背后的攻击。
- 过热、能量归零、死亡和复活均必须在同一物理帧关闭盾碰撞／防御资格。
- 空装备槽不能回退到隐藏默认武器。
- 迁移完成后，旧 `J / K` 操作从正式 InputMap 和玩家输入路径移除；测试直接注入新的模式与鼠标动作，不保留会造成双重控制的隐藏别名。
- 无缝分区加载失败属于构建／内容错误：开发和验证运行应明确失败；正式试玩不得静默传送到其他分区。

## 13. 验证策略

所有新增行为先以失败测试固定，再实现。

### 13.1 纯逻辑与输入

- `Q / E` 持续模式、模式切换仲裁、`1–4` 选择、空槽拒绝。
- 鼠标世界方向解析、左键路由、右键独立防御。
- 能量消耗、恢复延迟、护盾持续消耗、热量、过热和解除阈值。
- 正面普通格挡、重击穿透、背后攻击和攻击身份去重。
- 组合按键不能刷新腾空能力或制造二段跳。

### 13.2 机械爪与运行时

- 五种表面材质、距离、遮挡、吸附容差、单爪限制和失败原因。
- 墙壁、天花板、平台底部和边缘的真实碰撞射线命中；冰面、禁抓层、前景遮挡和纯视觉节点不能产生锁定。
- 发射、飞行、锁定、摆荡、收放绳、每次锁定一次空格跃升、松脱、收回和目标卸载的完整生命周期。
- 连接时空格不得收回绳索；同次锁定的第二次空格不得再次增速；落地或重新锁定后恢复资格；无绳时仍只有一次普通跳跃。
- 世界表面牵引玩家、轻型敌人拉近、重型敌人暴露、机关触发。
- 举盾时保留已连接绳索但暂停收放，按 `Q` 安全收回。

### 13.3 关卡与恢复

- 每个主线路段用真实物理探针从多个合理起点通过。
- 必经段不得使用二段跳，不得要求空中冲刺，不得依赖未教学组合键。
- 每个必要机械爪段必须真实使用地形或专用锚点完成，并验证失败承接层能够返回同段重试。
- 两个可选区域失败或跳过均不阻塞主线。
- 两个检查点、预检查点死亡、Boss 重试、捷径、分区卸载和旧存档迁移。
- 分区衔接时镜头、玩家速度、能量、热量、模式和装备槽保持连续。
- 坠落报告必须保留精确坐标、最后落脚平台、机械爪上下文和检查点，且不能把自动运行标为真人体验。

### 13.4 完成交付门禁

- `.NET` 构建 0 警告、0 错误。
- Godot 导入和启动没有非预期错误、泄漏或失效节点。
- 更新后的完整 `verify-prologue.ps1` 全绿，并真实覆盖新的连续拓扑与键鼠操作。
- Windows 显示、固定 60 FPS 的生产审计保持 50 ms 峰值预算。
- 重新生成 1280×720、60 FPS 完整流程与 Boss 重试录像；审查关键帧、输入反馈、抓取表面、护盾、过热、分区衔接、检查点和结算。
- 一次没有长时间闲置的正常速度真人试玩完整通关，目标仍为 10–15 分钟；记录最不顺或最不清楚的一处并完成对应问题闭环。
- 上述玩法和真人验收完成前，不进入正式美术生产。

## 14. 推荐实施顺序

1. 输入模式、装备槽和统一状态帧。
2. 能量模型、护盾防御分类和 HUD 反馈。
3. 机械爪模型、混合地形射线、锁定跃升与旧敌人／机关适配。
4. 连续世界分区控制器、五段 U 型峡谷与约十五个密闭多层微场景灰盒。
5. 检查点、复活、捷径、指导、音频和表现接口。
6. 完整迁移验证、性能审计、证明录像和正常速度真人试玩。

每一步结束时工程必须可运行，并保留现有用户工作区中的无关修改。旧房间切换路径只有在新连续世界对应行为和证据已经通过后才能删除或退役。
