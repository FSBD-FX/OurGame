# 连续峡谷序章与点按自动牵引设计

日期：2026-09-09。版本：设计 v2（场景丰富度补充）。

状态：用户先批准方向，随后回复“全部批准，丰富场景，现在场景过于单调”；本设计按全部批准进入实施计划，并按随后“时间太短”的反馈增加首次试玩时长目标。现有通路/存档故障的独立修复先行；本文不把设计或自动测试当作成品。

用户随后明确要求至少十种不同玩法场景、左右横跳峡谷、长下落深渊，以及更多机关、障碍和怪物；时长可以继续增加。再要求改为目标推进、取消自动化：`automation-9` 已正式删除，完整目标已创建，不恢复定时运行。

## 1. 目标与取舍

让第一关同时具备直接的地形牵引、有辨识度的探索路线、容易理解的战斗，以及可靠的开始—探索—Boss—出口—继续流程。

首次主线试玩以 20–30 分钟、含支路探索以 30–45 分钟为待真人验证的设计目标；不是交付日期、固定下限或已测成绩。统计主动游玩时间，暂停/离席不计入，不靠反复死亡、怪物增血、强制等待或重复跑图凑时长。若首次实测仍短，增加有新内容的区域/遭遇/探索奖励；不能阻止熟练玩家更快通过。

采用“自动牵引为默认、摆荡为可选技巧”。纯物理摆荡仍需要持续控制，不符合用户要求；直接瞬移虽然简单，却跳过地形与动作，因此不采用。自动牵引沿可见的空间连续移动，速度与碰撞受控，不寻路绕过墙壁。

当前存档与代码证据见 `docs/playtests/2026-09-09-boss-exit-and-continuous-world-feedback.md`。过去“不扩大盆地样板”的阶段范围被这次明确批准的方向替代；不因此声称当前已有完整第一关或达到商业目标。

## 2. 分段交付顺序

1. **P0 可靠性修复**：Boss 出口、世界外坠落恢复、神殿检查点继续。现有模式内修复，不偷渡新机械爪或新地图。
2. **新机械爪**：真实墙/顶/边缘，点按后自动牵引、安全挂接、松爪弹出、取消规则、匹配动作/UI/声音。
3. **连续地图**：用验证后的牵引能力校准通路，完成主线、支路、回环与捷径，不以旧 W 操作路线作为唯一测试脚本。
4. **探索与视听整合**：遭遇编排、短暂环境引导、背景/前景深度、身体和绳索反馈，最后从正常入口完整试玩并冻结有明显体验提升的候选。

每段是完整目标的依赖步骤，不得把其中一段通过称作全部完成。保留原始 ZIP，不覆盖用户当前 b98 运行目录或存档。

## 3. 操作契约

| 输入 | 新规则 |
| --- | --- |
| A/D | 地面/空中移动；已挂接时提供切向微调，可形成摆荡 |
| Q | 攻击模式；若机械爪活动，先清理挂接，再允许后续攻击 |
| E | 机械爪模式；切换本身不发射 |
| 左键，机械爪空闲 | 以点击时鼠标位置选目标，发射并锁定；松开鼠标不会收回，命中后自动牵引 |
| 左键，机械爪活动 | 取消本次牵引/挂接；下次点击可重新发射，不隐式把旧惯性叠到新目标 |
| 空格，未挂接 | 保留正常跳跃；不新增普通二段跳 |
| 空格，已挂接 | 一次性受控跃出并松爪，继承一次实际运动惯性，不在同帧再接受普通跳跃 |
| W/S | 不再是牵引通关的必要输入；新自动牵引模式不做手动收放绳 |
| Shift | 保留冲刺；活动牵引先取消，再执行原冲刺资格判断，不返还空中冲刺 |
| 右键 | 中断机械爪并举盾；原能量消耗/过热规则继续有效 |
| 1–4 | 保留道具/武器选择接口，不增加尚未设计的新武器 |
| Esc | 暂停，冻结牵引/引导计时与移动；恢复不触发重复点击/弹出 |

同帧优先级：死亡/恢复/暂停与目标卸载 > 防御或 Q 切换 > 冲刺 > 已挂接的空格跃出 > 左键发射/取消 > A/D 微调。冲突输入不同时叠加牵引、冲刺、弹出和普通跳跃。

同帧冲突边只执行最高优先级，其他边当帧消费、不缓存到下一帧；清理可先执行，但不再叠加低优先级速度。RMB＋Space 只取消并举盾，Dash＋Space 只执行有资格的 Dash，Q＋LMB 只切换攻击模式，此次 LMB 不攻击也不发爪。暂停恢复不会重放暂停前的发射/跃出边。

机关/敌人的旧机械爪交互保留“命中→触发效果→收回”，不把玩家拉进敌人或机关内部。主路只使用可拉动玩家的地形抓附来承担移动教学。

## 4. 牵引状态与身体安全

继续复用已有状态与表现接口：空闲 → 瞄准/发射准备 → 飞行 → Reel（自动牵引）→ Swing（到达后挂接）→ Released → Retract → 空闲。持按与松开不再控制是否保持本次抓附。

空格跃出作为单次事务发布一次 Boost/跃出事件并在同一事务进入 Released；音频/VFX仍收到一次起音/动作事件，Motor只采纳一次最终释放速度，不用“先Boost一帧、下一帧再Release”的两次加速。

初版调参起点：保留 620px 射程和 36px 目标辅助；自动收绳 540px/s、最大朝向目标速度 720px/s、朝向目标加速度上限 2400px/s²、飞爪速度 1800px/s、近目标减速距离 160px。这些是待实测的起点，不是已验证的手感结论；数值集中配置，不能散落在状态或地图脚本内。

验收以真实运动而非上述常量为准：从静止点击前方约 400px 的有效目标、不按 W 或持续左键，人物可连续拉近，末端不硬撞、不抖动。正常速度下，无遮挡且不需要越障的参考场景，从点击到安全挂接目标为 0.8–1.4 秒；测试同时记录轨迹和输入到可见响应的延迟，不能通过传送或等待凑时长。

安全规则：

- 抓点必须来自真实可抓地形表面，保存世界命中点、法线、目标标识、材质与有效性；悬空辅助点可以保留，但不得作为主路唯一可抓物。
- 石材/金属可抓，冰面/封板不可抓。准星在发射前区分有效、超距、遮挡和滑冰拒绝，失败不扣除未设计的额外代价。
- 持续检查视线与真实玩家碰撞形状的运动扫掠。贴靠目标本身是预期接触，中途其他地形挡住则停止牵引并安全释放；不穿墙、不绕墙自动寻路、不修改 GlobalPosition 来假装平滑。
- 停靠点根据胶囊尺寸、命中法线和最短安全绳长计算；不能把人物中心吸到命中像素。有效挂接后保持受控张力，允许 A/D 或空格离开，不要求再次 W。
- 每帧先按命中法线与玩家碰撞形状的安全站距判断到达，再处理受阻计时。进入安全停靠包络即可到达，不要求胶囊实际撞上目标；若确实接触目标，法线必须匹配保存的命中面，同一地形的其他面或提前发生的接触算受阻。仅在未到达包络内连续 0.25 秒没有有效进展时释放并提示受阻；正常挂接不累计超时。实际碰撞体仍有远离停靠点的惯性、且连续观测速度证明正在有界减速时，属于有效进展，减速期间重置停滞计时及距离基准；只有拟施加的拉力、没有实际速度改善不算进展。不延长停滞时限、不放宽安全站距。
- 空格跃出只继承一次碰撞后的实际速度；基础速度、实际牵引与跃出合成后，去掉朝接触面的径向分量，再将最终合速度限制为初始 900px/s（不改变独立冲刺的既有速度）。角色没有成功挂接时不能获得这个空中跃出资格。取消、落地、死亡、目标卸载、新局和继续均清除旧牵引状态。
- 高处主路的首次牵引有可见落脚地和下方容错面；不要求玩家在初次使用时掌握连续空中再挂。

动作与声音读取真实状态：抬手发射、收绳承力、披风随速度滞后、近目标收势、松爪跃出必须连贯。绳索可有克制的视觉弧度，不以整个人物图片缩放/拉伸模拟动作。现有开爪、命中、牵引和跃出音事件保持去重，且关键起音不被连续收绳音吞掉。

## 5. 连续地图与探索结构

设计模式采用 `generate2dmap` 的 `side_scroll_mode`：分层背景 + 独立地形/机关/遭遇 + 精确碰撞 + 场景事件标记。碰撞与抓取规则不从背景图像推断。

当前引擎视口是 1280×720，继续作为预览与构图标准。新关卡初版横向容纳 6 个视口宽（7680px），纵向可布置到 6 个视口高（4320px），给可控深渊与回升路线留足空间；这不是 36 个要塞满的房间，也不以跑动距离衡量内容质量。背景可循环复用，实际平台、壁面、出口、检查点与镜头关注区均单独配置。

### 5.1 玩法类型门槛

至少 10 种实际可玩的不同场景类型；初版按以下 12 类编排。每类必须包含独立的操作、路线判断或探索收益，不能以旧微场景名字、背景配色或重复台阶冒充差异。

| 类型 | 核心玩法与安全边界 |
| --- | --- |
| 交错裂谷 | 左右换壁、短横跳与点按抓附；下方有容错台，不要求普通二段跳 |
| 可控深渊 | 允许约 4–6 秒连续下降的路线，侧壁可抓制动、中途有出口、底部安全落点；镜头向下前瞻，不做盲落或强制空等 |
| 低顶断桥 | 横向选择梁底与桥边抓点，身体净空真实可过，与竖直上升明显不同 |
| 配重竖井 | 可承载玩家的升降配重、停靠层选择与回程捷径，不是只移动图形 |
| 冰封回廊 | 明确不可抓冰面与可抓岩壁组合，观察材质并选择绕行路线 |
| 齿轮工区 | 齿轮/活塞的清晰工作节奏、避让凹位与穿越窗口，首次在安全区示范 |
| 蒸汽泵房 | 操作阀门改变喷汽路径或开放通道，危险前兆与有效范围一致 |
| 钟摆走廊 | 钟摆周期与安全停留点，允许稳妥通过，不靠极限帧数 |
| 档案侧洞 | 支路探索、发现与补给，以及可辨识的返回回环，不是空终点 |
| 双层遭遇 | 同一空间的高低路线、敌人分隔与绕背选择；地形应遮挡不合法攻击 |
| 封印外院 | 解锁侧路或机关后汇合的短目标链，机关完成产生持久可见变化 |
| Boss 厅 | 预判—应对—反击的阶段战斗，战前检查点、战后明确安全终点 |

机关至少覆盖升降配重、阀门改道、活塞阻挡、钟摆时机、可开启捷径、封印联动六种功能；仅更换外观不另算一类。主路先给安全示范，再组合已经教过的规则。长下落不是强制等待：制动、侧出口与快速下降都应有作用，实测不足时调整空间，不降低重力来硬凑秒数。

20–30 分钟主线、30–45 分钟探索仅是初版时长起点，不是上限；通过新内容增长时长，不拖慢既有动作或用相同遭遇重复填充。

### 5.2 连续空间组织

主线连续构成 U 形：

```text
峡谷断桥入口                         上层回廊 ─ 神殿外院 ─ Boss 厅 ─ 安全出口
     │                                   ▲
 起重机竖井 ─ 旧档案室                    │
     │          └─ 维修通道 ─┐         配重井
     ▼                      ▼            ▲
 底层遗迹 ─────────────── 盆地营地 ─ 齿轮泵房
                             └─ 排水侧道 ─┘
```

空间原则：

- 主路覆盖下降、水平穿行、侧向抓壁与上升，不再连续堆叠悬空小平台。
- 至少三个可行走高度层；洞室、厚墙、梁底与连廊形成局部闭合空间，开放景观用于辨识方向和节奏缓冲。
- 两条可形成回环的支路：档案室—维修通道回盆地；泵房与排水侧道殊途汇合。支路提供补给、发现或更安全的通过方式，不只是空洞末端。
- 一条从上层回廊解锁回盆地的持久捷径；首次看到时能理解其目的，开启后降低回程重复劳动。
- 主要上升通路使用墙面、梁底和边缘的实际抓附；至少一条分支允许不同的抓附点选择，而非固定连线顺序。
- 关键路径不依赖普通二段跳、极限盲抓或未获得的道具。对抓附面被遮住、身体净空不够或镜头看不到落点的跳跃，改地形而不是加隐藏助推。
- 玩家可看到返回方向和下一个落脚面；前景遮挡不能盖住角色的身体、脚下支撑或关键抓点。

技术上仍允许后台按区块加载，但玩家使用同一个 PlayerRoot 与世界坐标。普通跨区不切黑、不弹关卡卡片、不传送人物、不突然把镜头吸到新房间中心。加载提前覆盖所有可见与可到达邻接区域；分支/回环需要明确邻接关系，不能继续只依赖 Previous/Next 链。

拥有当前活动抓点的区块在机械爪 Released/Idle 前保持驻留；跨缝时玩家区、目标区与可用落脚区同时驻留。若目标被破坏等外部原因强制失效，先完成松爪和速度清理，再卸载目标，且保留落脚区，不能在半空因后台清理突然丢掉抓点与地面。

## 6. 遭遇与引导

初版编排目标：主路八处普通遭遇、支路四处普通遭遇、一场 Boss。普通遭遇复用现有敌人行为与可替换表现资产，至少包含单敌读招、破甲应对、双层绕背、窄路诱导及两敌空间分隔组合，并与上述场景类型配合。不是要求每个画面常驻怪物；按批次激活，首轮普通遭遇最多两个同时进入有效攻击范围，营地不主动接敌。遭遇总量增加不等于同时围攻数量、伤害或血量增加。

战斗前给可观察空间，攻击有真实对应的前摇、危险范围和恢复窗口；复杂度来自站位和路线选择，不靠提高伤害或血量。至少一个支路能绕开非关键战斗，不要求清图才开所有门。Boss 前有可继续的检查点及休整空间，击败后必须有明确的安全终点。

萤火虫引导作为独立的首关辅助：

- 首次到重要岔路、Boss 出口解锁、或玩家在尚未推进的区域约 18 秒没有接近任何可行路线时出现。
- 一次最多引导到下一个局部路口/落脚面，持续约 3 秒，至少 15 秒冷却；已经访问并理解的路段不持续重复。
- 引导路径来自可达路线标记与门/机关状态，不对关闭门、不可抓冰面、未加载区域或无支撑空洞发出前进信号。
- 战斗危险前摇期间推迟显示；暂停冻结计时；完成、返回标题、恢复、新局时清理。
- 到下一个关键路口后用环境地标继续接力。除安全失败原因和首次必要键位外，不再常驻大段操作卡。
- 只属于第一关，沿用辅助开关；新图教学以 E→点击→自动拉近→空格离开为序，不残留“必须 W”的提示。

## 7. 出口、存档和异常恢复

P0 与新地图共享可靠性原则，但不能把相机 Bounds 当作全部可玩范围：正常跳跃、抓附弧线、邻区接缝与回环都有独立可达空间。超出任何合法空间且没有合法落点时，走既有恢复事务；只恢复一次，清速度/爪/死态并回到已激活检查点，没有检查点才回开局。

Boss 后出口进入明确结束区，展示正确的开发候选/试玩完成含义，并提供返回标题与重玩；没有下一段内容时不能开一扇通向虚空的门。结束状态不能继续驱动人物跌落，也不能重复写结算或恢复。

保存与继续使用同一合法检查点规则。新图另设布局版本和检查点 ID；旧档案保留，不能把旧坐标套到全新地形。能映射到安全检查点的旧进度可迁移，否则明确提供保留旧档、从新版起点开始的选择，不静默覆盖。旧 b98 没有保存的 Boss 击败事实无法可靠补造。

序列化 schema version 与地图 layoutVersion 是不同字段；检查点、发现和捷径各使用布局内稳定 ID，由显式迁移表映射。首次写新版前保留原存档文件/旧槽；迁移失败或用户尚未选择时不调用 SaveAtomic 覆盖原档。

独立开发样板和完整序章存储继续隔离。支路发现、持久捷径与真实 Boss 击败进度逐项保存；样板仍不得伪增正式通关或真人最佳成绩。合法检查点匹配作者声明的检查点/起点，而不只是允许某扇区的任意半空坐标。进度不是根据角色路过某个未来区域就自动补全。

## 8. 实现边界与资源接口

在现有模块上按职责改动：输入采样与模式分派、MechanicalClawModel/Controller、TargetResolver、PlayerMotor、世界加载/恢复、GameFlow/Completion、地图构建数据、环境引导、动作/UI/音频适配。

地形构建数据是玩法源，背景和平台皮肤仅是可替换表现。保留场景层、地形层、角色、敌人、UI、VFX/音频的独立资源接口。先复用已有合法资产和用户已允许的结构占位，不把程序化占位说成正式美术。

本次不添加新的远程武器、付费系统、广告/招募、云端数据收集或后续章节；不承诺玩家数量或交付日期。需要生成正式资产时单独说明用途、成本和不可替代原因，并取得付费确认。

## 9. 验收证据

### P0

- 正常 Boss 战获胜后持续向右、转向左、从出口跳出；始终处于可操作的安全场景、恢复流程或明确结束界面，不能只剩镜头。
- 正常死亡与坠落各只恢复一次；初次死亡不能前移到未激活检查点。
- 在各合法检查点退出再继续；核对实际位置、存档状态及 Boss/捷径重建。无效/外部路径档案继续拒绝。
- 普通序章和独立样板分别验证，不以关闭出口掩盖断路。

### 机械爪

- 点击只保持一帧后松开，完全不按 W，分别从地面/空中拉向墙、天花板、凸边；记录实际轨迹与到达时间。
- 近目标减速、不穿薄墙、不持续压墙；中途出现障碍、目标卸载、超距都安全释放。
- 冰面拒绝；普通跳跃不增加次数；空格/冲刺/盾同帧不叠加额外速度或返还资格。
- 死亡、新局、继续、暂停和跨区无残留线条、速度修正或输入。

### 地图与体验

- 至少十类不同玩法场景实际通过；逐类记录操作/判断差异、机关状态变化、奖励及恢复路径，不以命名或背景数量验收。至少六类机关具有真实碰撞/交互与路径作用。
- 左右换壁裂谷与可控深渊必须实跑；深渊检查向下前瞻、点击抓壁制动、中途退出和底部落地，不能只验证从高处传送到底部。
- 正常入口全主路、两条回环、持久捷径和 Boss 后出口全部真实走完，不靠传送完成主要路径。
- 每次跨区从往返两个方向验证；站立/跳跃/拉爪时人物与地形连续可见。
- 所有萤火虫目标可达，关闭门和冰面不会误导；关闭辅助也能从环境读出主路。
- 普通窗口实际检查 UI、角色/敌人前摇、抓爪动作、音频和遮挡，录制并审看短片；自动驾驶不等于真人上手。
- 邀请用户试玩该冻结候选并记录迷路点、卡住点、手感与画面反馈。记录主线及含支路的首次主动游玩时间，分别对照 20–30/30–45 分钟设计目标；此前 5–8 分钟不再约束新连续关卡。不把代理路线、暂停或无聊重复当作真人时长证据。

只有上述证据和用户品质反馈支持时，才称本轮候选有显著提升；再独立编号打包，并依既有 GitHub 私有归档规则核验。自动化运行次数、测试数量和主观估计不用于推算十万付费玩家。
