# 《无名钟楼》序章第一关完整制作规格

**日期：** 2026-08-17
**状态：** 已由“全部正式完成后再交付游玩”的成品简报授权执行
**项目：** `E:\OurGame\Knight`
**范围：** 完整序章第一关的正式 UI、美术、动画、特效、音频、设置、演出与最终交付

## 1. 目标

把已经可完整运行的六房间灰盒序章升级为一段约 10–15 分钟、可独立交付的正式第一关。最终交付不再以“玩法完整但使用占位表现”为完成条件；玩家看到的角色、敌人、Boss、场景、机关、HUD、菜单、提示、特效和音频都必须属于同一个完成度一致的正式版本。

本轮不在中途交付零散半成品。制作期间仍持续自动验证和内部运行审查，但只在所有完成门槛通过后启动最终版本供用户游玩。

## 2. 已锁定的制作决策

### 2.1 视觉方向：暗铜童话

- 世界基调为破败钟楼、黑暗童话与精密机械的融合，不复制《空洞骑士》的角色轮廓、面具、地图、美术或演出。
- 主色为冷黑、深蓝灰和氧化铜绿；交互与引导使用旧金；生命与危险使用受控锈红；机械丝、灯芯和记忆状态使用低饱和青白光。
- 画面使用干净、可读的手绘分层形体。纹理只服务于材质和空间层次，不用高密度随机噪点制造“细节”。
- 金属细节集中在轮廓节点、关节、钟链和重要机关；布料、石材和远景保留大色块，避免全画面机械零件化。
- 角色、敌人和可交互目标必须在 1280×720 的实际游戏视距下先通过轮廓和动作读取，再考虑近距离纹理。

### 2.2 主角方向

- 主角保持小体型、低重心、细长针剑/半钟刃和深色布质斗篷。
- 肩背装置与悬浮灯是身份重点，但不能把身体扩张成笨重机器人。
- 悬浮灯位于头顶后方，借柔性发光能量丝连接肩背核心；待机、奔跑和空中运动具有不同的滞后、摆幅和回弹。
- 斗篷是连续布料主体，运动表现包含拖拽、折叠、回弹和落地余振，禁止仅对整张图做拉伸、旋转或上下浮动。
- 先前被用户否决的 A2 完整穿戴成图及其比例、笨重轮廓和大面积陶瓷躯体不得作为运行时成品、动画母版或敌人设计模板。
- 先前单独获批的部件只可作为结构参考；任何最终组合都必须重新通过小体型、布料动态和游戏视距可读性审查。

### 2.3 费用与来源

- 当前制作不调用按次计费的图像、视频、音乐或语音生成 API。
- 正式资产采用项目自有的分层矢量/位图创作、Godot 2D 绘制、着色器、骨骼/关键帧动画和可验证的本地后处理。
- `sprite-gen`、Agent Sprite Forge 和 Gorest 只用于切分、对齐、打包、元数据、预览与质量检查；它们不是原创像素来源。
- 若未来确实需要付费生成，必须先列出单次成本、用途和替代方案，并另行取得用户明确批准。
- 第三方字体、声音或纹理只有在许可证允许商业再分发时才能进入运行时；来源、许可证和修改记录写入资产清单。

## 3. 玩家体验与演出结构

### 3.1 启动与进入关卡

1. 启动后显示短暂工作室/项目标识和《无名钟楼》标题。
2. 主菜单只提供本阶段真实可用的选项：开始/继续、设置、控制、退出。
3. 新游戏以黑场、钟鸣和两行短叙事进入苏醒庭院；不播放不可跳过的长动画。
4. 首次取得控制时，移动、跳跃和当前目标均清楚可见，玩家可在两秒内理解行动方向。

### 3.2 六房间正式表现

- **苏醒庭院：** 冷月光、破裂拱顶、风动帘布和远处钟体剪影；空间开阔，适合读取移动与跳跃。
- **断齿回廊：** 墓灯检查点、断裂齿轮、第一场战斗和机械丝锚点；视觉密度开始增加，但交互金色轮廓始终清楚。
- **上层摆锤：** 高空、摆钟剪影、风压和纵向视差；强调空间危险与墓灯蛾的飞行轨迹。
- **下层埋葬机械：** 压低天花、活塞、旧管线和蒸汽；强调近战压力与锈壳侍从的防守轮廓。
- **钟链机关：** 巨型钟链、劳动平台和中央金色牵引点；中性 K 辅助命中必须在视觉和音效上显得自然。
- **坠落钟守竞技场：** 前半冷暗、转阶段锈红、暴露时青白核心；Boss 形态、攻击警示和可牵引锁链必须同时由动作、形状、声音和颜色表达。

### 3.3 结束

- Boss 倒下后恢复安静环境声，通往收束区域的出口明确亮起。
- 最终线索以短文本与场景物件共同呈现，不用长篇弹窗打断操作。
- 完成卡显示关卡名称、用时、死亡次数、隐藏路线和捷径状态，并提供“返回标题”与“再次游玩”。

## 4. 正式 UI 系统

UI 使用统一 `Theme`、九宫格面板、图标集、输入字形和动效时间表；玩法代码只传递状态，UI 不决定伤害、冷却、碰撞或通关。

### 4.1 HUD

- 左上角为五段“钟瓷生命片”，受伤时当前片破裂并短暂锈红闪动，恢复时以暖白重新拼合。
- 生命右侧为机械丝线轴：外环表示冷却，中心青白灯表示可用，命中时出现一次向外扩散的细线脉冲。
- 当前目标使用一行短文本，默认在状态变化时出现，数秒后折叠为小型目标符号；暂停菜单可重新展开。
- 第一关指导位于 HUD 下方独立面板，只在本关生效。它显示“下一步”、可选“提示”和世界目标标记，不与生命、Boss 条或暂停输入重叠。

### 4.2 世界与上下文提示

- 世界目标使用旧金菱形、边缘箭头、距离和短暂脉冲；屏内标记不遮挡角色或敌人头部。
- 按键提示位于底部中央，使用键鼠/手柄对应字形和动作名称；最后使用的输入设备改变时即时切换。
- 检查点激活、隐藏路线、捷径开启和能力可用均使用短横幅，不暂停游戏。
- 同一挑战连续失败两次后才显示强化提示；提示不修改角色属性或敌人行为。

### 4.3 Boss UI

- Boss 名称与生命条位于画面底部安全区，不占据第一关指导面板。
- 阶段、护甲和暴露状态通过生命条结构、中央图标和短文本共同表达。
- 转阶段时 UI 只做一次 0.35–0.5 秒的重组动画，不覆盖 Boss 攻击预警。

### 4.4 菜单与设置

- **主菜单：** 开始/继续、设置、控制、退出。
- **暂停菜单：** 继续、控制、设置、指导开关、返回检查点、返回标题、退出。
- **设置：** 主音量、音乐、音效、环境音；窗口/全屏、分辨率、垂直同步；UI 缩放；屏幕震动强度；闪光减弱；语言；指导开关。
- **控制页：** 同时展示键鼠与手柄；仅显示已实现动作。
- **失败恢复：** 不显示冗长死亡界面，使用 0.6–1.0 秒钟裂过渡、原因短句和快速恢复。
- **完成卡：** 显示真实统计，不把自动 smoke/capture 数据标成人类成绩。

### 4.5 分辨率与可访问性

- 设计基准为 1280×720，必须验证 1920×1080、2560×1440 和 3840×2160。
- UI 使用锚点与安全区，不通过整体位图拉伸适配宽屏。
- 文本最小字号、对比度和描边在所有目标分辨率可读；提示不只依赖颜色。
- 中英文文本使用统一字符串表，任何语言切换都不能改变节点路径或玩法逻辑。

## 5. 正式角色、敌人和 Boss 资产

### 5.1 主角动画集

至少包含：待机、起步/奔跑、刹停、起跳、上升、下落、落地、地面攻击、空中攻击、下劈、冲刺、机械丝施放、受伤、死亡/恢复。攻击判定继续由玩法时间轴驱动；动画只响应明确事件。

主角采用分层 2D 骨骼与关键姿势修形的混合方案：躯干、肢体、武器、斗篷、肩背核心、悬浮灯和能量丝分开。斗篷和灯具具备独立延迟曲线，关键攻击与落地使用少量逐帧修形，避免木偶感。

### 5.2 敌人

- **锈壳侍从：** 低矮护甲、明显防御壳和前方攻击面；待机、追击、预警、攻击、恢复、受击、眩晕和死亡均有不同轮廓。
- **墓灯蛾：** 轻薄翼面、墓灯腹部和清晰俯冲预警；飞行循环不能靠整图正弦漂移冒充振翅。
- **钟背苦役：** 背负钟体、链条和沉重步态；可牵引/眩晕状态由链条张力与钟体姿态表达。

### 5.3 坠落钟守

- 体量明显大于普通敌人，但不能遮满竞技场。
- 第一阶段保持开放攻击姿态；第二阶段闭合护甲；投锤、锁链暴露和核心暴露分别具有唯一剪影。
- 至少包含待机、移动、普通预警/攻击、重击预警/攻击、转阶段、护甲关闭、投锤、被丝线牵引、暴露、受击、恢复、击败。
- 关键攻击预警不少于三种信号中的两种：姿势、地面/空间形状、声音；颜色只能作为补充。

## 6. 场景美术与关卡皮肤

### 6.1 分层结构

每个房间至少拥有：远景、后景、中景、可碰撞平台皮肤、独立机关/道具、前景遮挡和氛围层。所有视差层共享相同相机基准、地平线和段落尺寸；碰撞仍来自现有玩法几何，不从背景像素推断。

### 6.2 共用资产库

- 石材边角、破裂平台、金属梁、齿轮、链条、管线、栏杆、布帘和装饰钟体形成可复用模块。
- 墓灯、机械丝锚点、钟链目标、门、捷径和 Boss 锁链是独立可交互场景，不烘焙进背景。
- 平台顶缘、危险边缘和非碰撞装饰有稳定的视觉语法，玩家不需要试错才能判断落脚点。
- 前景遮挡在角色进入其后方时降低透明度，不能隐藏敌人攻击或目标标记。

### 6.3 灯光和氛围

- 使用 2D 灯光、局部雾、尘埃、蒸汽、细小灰烬和受控的屏幕空间暗角。
- 同一房间不叠加多种高频粒子；粒子密度随战斗和镜头远近调整。
- 正常状态以铜绿/青白为主，Boss 高压状态引入锈红，完成后回到月银与暖白。

## 7. 特效、镜头与反馈

- 武器挥砍、命中、受伤、护甲格挡、下劈落地、冲刺、机械丝、检查点、捷径、Boss 转阶段和击败均有独立特效。
- 机械丝由起点、动态曲线、命中端点、张力和消散五部分组成；端点必须与真实 `ThreadTarget2D` 重合。
- 命中停顿、镜头震动、缩放和色闪均有上限，并受设置项控制。
- 普通战斗不使用长时间全屏闪白；Boss 转阶段也保留玩家和危险物的轮廓。

## 8. 音频

- 音频总线分为 Master、Music、SFX、Ambience 和 UI。
- 探索音乐使用低频钟鸣、弓弦金属与稀疏织体；上/下分支通过配器而非完全换曲区分。
- Boss 曲分两层：第一阶段节奏克制，第二阶段加入锈铁冲击和更强低频；击败后自然退回环境声。
- 每类敌人、玩家动作、机关、检查点、UI、失败恢复和 Boss 状态都有可辨识声音。
- 脚步、攻击和命中使用小型受控变体池，避免完全相同的重复采样。
- 所有声音必须原创、项目自有或许可证明确；资产表记录来源与许可证。

## 9. 技术架构和替换边界

- 现有 Gameplay 根、碰撞、状态机、伤害、冷却、检查点和房间链接保持为权威数据。
- `VisualRoot`、表现协调器和 `PresentationProfile` 继续作为正式资产入口；不得让贴图文件名或动画帧决定玩法。
- UI 状态通过独立 view model/事件绑定，不从场景颜色或 Label 文本反解析玩法。
- 正式资产按 `player`、`enemies`、`boss`、`environment`、`ui`、`vfx`、`audio` 分类；原始制作文件保留在外部美术工作区，运行时只发布最终资产和清单。
- 场景继续由 C# builder 生成，叶场景先于父场景；每次打包后实例化并比较节点数。
- 缺失正式资产时开发构建可显示诊断替代物，但最终验收会把任何可见替代物、缺失纹理、缺失音频或回退字体判为失败。

## 10. 数据、存档和统计

- 保存设置、当前关卡、最近检查点、隐藏路线、捷径和是否已通关；失败恢复不清除永久进度。
- “继续”只在存在有效存档时启用；损坏存档回退到安全默认并显示非阻塞提示。
- 完成统计记录真实玩家会话来源、用时、死亡、Boss 尝试、隐藏路线和捷径；自动录屏和 smoke 数据不能混入真人成绩。

## 11. 测试与验证

### 11.1 自动门禁

- `.NET 9` 构建无警告无错误。
- 所有 builder 成功，生成场景打包/实例化节点一致，生成前后语义无漂移。
- 现有模型、结构、集成、指导与完整 critical-path 测试继续通过。
- 新增 UI 状态、设置持久化、输入字形切换、本地化、音频总线、动画状态映射、资源清单和缺失资产失败测试。
- 1280×720、1920×1080、2560×1440 和 3840×2160 截图验证 HUD、Boss UI、暂停菜单、设置和完成卡无重叠、裁切或越界。
- 运行日志不得出现 `ERROR`、`SCRIPT ERROR`、`Parse Error`、缺失资源或非法节点路径。

### 11.2 可见验收

- 录制覆盖开场、移动教学、检查点、上下分支、三类敌人、钟链、中性 K、Boss 两阶段、失败恢复和完成卡的完整证明视频。
- 逐段检查角色轮廓、斗篷动态、灯具滞后、攻击接触、机械丝端点、平台可读性、预警、UI 动效和声音同步。
- 在目标硬件上保持稳定 60 FPS；无持续卡顿、输入丢失、导入停顿或音频爆音。
- 最终只启动通过上述门槛的成品供用户试玩，并以真人 10–15 分钟完整通关作为最后验收。

## 12. 完成定义

只有同时满足以下条件才可称为“第一关正式完成”：

1. 六房间流程、三类敌人、检查点、上下分支、钟链、Boss 和收束均可完整游玩。
2. 所有可见灰盒、程序化占位角色、占位 UI 和调试文字已由正式表现替换。
3. 主角、敌人、Boss、机关、场景、动画、特效、音频和全部 UI 属于同一视觉语言。
4. 主菜单、HUD、引导、Boss UI、暂停、设置、控制、失败恢复和完成卡全部可用。
5. 存档、设置、键鼠/手柄、分辨率、UI 缩放和可访问性选项通过验证。
6. 资产来源、许可证、制作文件、运行时文件和替换接口记录完整。
7. 自动门禁、全流程运行、性能审查、证明录屏和日志扫描全部通过。
8. 用户获得的是最终构建，而不是内部录屏驱动、旧进程或修复前窗口。

以上任一项缺失时，目标保持进行中。
