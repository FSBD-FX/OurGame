## 1. 背景与目标

当前第一关已经具备完整路线、战斗、机械丝、检查点、Boss、UI、音频和可运行交付，但真人试玩未能通关。最近一次真人报告记录了 30 次死亡，其中普通路线 5 次、Boss 25 次；最终停留在 `FallenBellkeeperArena / DefeatBellkeeper`。玩家反馈集中在四类问题：

1. 敌人攻击缺少可具象化、可提前判断的表现，作为第一关偏难。
2. 场景、怪物、UI 与动作仍显单调，缺少材质、景深、轮廓和节奏层次。
3. 机械丝不顺滑、动作不连贯、视觉过短、技能形态不明确，使用成功或失败的原因也不清楚。
4. 玩家跑跳、攻击和机械丝动作缺少明确准备、爆发、命中与收势姿势。

本设计以“先建立可靠的可读性和状态边界，再持续美化”为路线，把玩法判定、动作表现、场景美术、HUD 与音频接到同一套可测试的状态数据上。目标不是一次性增加装饰，而是形成可以持续实机体验、纠正和升级的表现架构。

本设计覆盖并细化上位完整制作规格；如两者在第一关攻击提示、机械丝流程、动作节奏或 HUD 密度上存在冲突，以本设计为准。

## 2. 已批准方向

### 2.1 操作与难度

- 机械丝采用混合输入：轻按 `K` 自动锁定，长按 `K` 进入瞄准，松开施放。
- 第一关所有敌方攻击采用统一三段预警：金色蓄力、红色真实危险范围、白色命中确认。
- 第一关采用教学友好难度；后续关卡不自动继承同等强度的范围提示和宽容参数。
- 普通敌人的有效前摇目标为 0.55–0.80 秒，Boss 为 0.75–1.00 秒；每种攻击的最终值由实机试玩校准。
- 普通接触和单次攻击原则上只造成一格伤害；Boss 前保留稳定检查点。

### 2.2 视觉方向

- 第一关采用“暮钟工业遗迹”：锈铜、旧石、木梁、钟械和受控雾尘组成多层空间。
- 旧金用于引导和可交互信息，青色专属玩家机械丝，红色只用于危险，白色用于武器和命中瞬间。
- 怪物采用 AC 融合的中度腐化：旧钟城侍卫、灯工和劳工的身份与武器轮廓占主体；约三成甲壳、菌丝与裂纹集中在非武器侧、背部和外轮廓。
- 腐化不得遮挡武器、头部朝向、起跳动作、攻击轨迹或脚部接地。
- 不使用按次付费的图片、视频、音乐或语音生成。本轮继续以项目自有的程序化矢量、分层位图、本地后处理、Godot 动画和可替换资源完成。

### 2.3 机械丝与动作

- 机械丝的实体表现为“丝梭针”：肩部线轴蓄能，角色挥臂射出针形丝梭，命中后展开菱形锁扣，三股机械丝绷紧再牵引。
- 动作采用“清晰弹性”：明显但短促的准备、快速爆发、可见的命中停顿、允许被移动取消的收势。
- 披风、悬浮灯、肩部线轴和腐化挂件使用独立延迟、回弹与惯性，不再随躯干逐帧硬切。

### 2.4 HUD

- HUD 采用紧凑分层：生命和机械丝合并为左上仪表，任务压缩为单行，世界操作提示靠近目标，Boss 血条贴底。
- 第一关教学只在首次触发、连续失败或玩家主动重开时展开；正常战斗不长期显示大面积说明面板。

## 3. 架构原则

### 3.1 判定与表现解耦

玩法模型是伤害、碰撞、目标选择、冷却、牵引、房间进度和 Boss 阶段的唯一权威。表现系统只能读取不可变状态帧和明确事件，不得通过贴图、颜色、粒子位置或动画帧反向决定玩法。

攻击范围可视化必须由真实攻击数据生成，不能维护另一份手绘尺寸。机械丝的飞行、锁扣和绷紧表现必须跟随玩法状态；视觉丢失或资源缺失不能改变命中结果。

### 3.2 小型可替换单元

本轮按以下职责边界组织：

- **攻击描述：** 提供阶段、攻击类型、方向、真实形状、剩余时间和锁定信息。
- **敌人预警表现：** 把攻击描述渲染为姿势、范围、声音和命中反馈。
- **机械丝施放模型：** 管理输入意图、目标、飞行、锁定、作用、失败和冷却。
- **机械丝表现：** 管理线轴、手臂姿势、丝梭、锁扣、三股丝和音效。
- **玩家动作混合：** 组合移动层、行动层和次级运动层。
- **敌人动作表现：** 把各自状态转换成独特轮廓和动作时间线。
- **房间表现：** 从房间配置生成远景、中景、游戏层皮肤、前景和氛围。
- **HUD 视图：** 只读取生命、能力、目标、提示和 Boss 状态。

每个单元通过窄接口通信，可单独替换、测试和捕捉；不得把所有表现堆入单个场景脚本。

## 4. 敌人攻击可读性

### 4.1 统一攻击数据

每次敌方攻击输出一个攻击描述，至少包含：

- `AttackId`：单次攻击的稳定身份。
- `Phase`：`Telegraph`、`Active` 或 `Recovery`。
- `Kind`：刺击、横扫、俯冲、落地、地面波、投锤等。
- `Shape`：线段、胶囊、扇形、圆形或地面带。
- `Origin`、`Facing`、`Extent`：与真实判定一致的空间数据。
- `PhaseDuration`、`PhaseRemaining`：驱动姿势、填充和声音。
- `LockedTarget`：攻击是否已锁定位置，避免红区与最终攻击漂移。

第一关预警表现使用该数据绘制金色准备轮廓和红色真实危险区；进入 `Active` 后切换为白色武器/落点闪光，红区立即消退，避免玩家误认为仍可受击。

### 4.2 普通敌人动作语言

- **锈壳侍从：** 盾壳收紧、身体压低、武器后撤，再沿红色直线刺击。恢复时枪尖下垂，明确给出反击窗口。
- **墓灯飞蛾：** 停止常规扇翼、折翼并点亮金色眼灯，锁定红色俯冲线和落点；俯冲方向在前摇结束前固定。
- **背钟劳工：** 双脚扎稳、身体逆向扭转、抬锤蓄力，再扫过红色扇形；背钟和菌丝的滞后不能遮挡锤头。

### 4.3 Boss 动作语言

坠落钟守的横扫、跃击和地面波必须具有不同准备轮廓、攻击形状和起手声音：

- 横扫强调水平拉伸和扇形危险区。
- 跃击强调压低、腾跃、锁定落点和圆形冲击区。
- 地面波强调举锤、地面蓄光和单向或双向地面带。
- 投锤、护甲闭合、锁链暴露、核心暴露继续使用现有阶段语义，但各自具有唯一剪影和声音。

第一轮平衡以降低无信息受击为目标，不通过隐藏缩小判定欺骗玩家。Boss 耐久和恢复窗口根据真人尝试数校准，使首次玩家预计在 2–6 次尝试内完成。

### 4.4 首轮平衡基线

实现首轮使用以下明确基线，之后只有在保存真人试玩证据后才能调整：

| 对象/招式 | 前摇 | 生效 | 收势 |
| --- | ---: | ---: | ---: |
| 锈壳侍从刺击 | 0.65 秒 | 0.14 秒 | 0.65 秒 |
| 墓灯飞蛾俯冲 | 0.70 秒 | 0.35 秒 | 0.70 秒 |
| 背钟劳工横扫 | 0.75 秒 | 0.20 秒 | 0.70 秒 |
| Boss 横扫 | 0.80 秒 | 0.25 秒 | 0.70 秒 |
| Boss 跃击 | 0.90 秒 | 0.25 秒 | 0.75 秒 |
| Boss 地面波 | 1.00 秒 | 0.30 秒 | 0.75 秒 |
| Boss 投锤 | 0.85 秒 | 沿用真实飞行时间 | 0.70 秒 |

Boss 首轮生命值设为 12，玩家每次有效攻击造成 1 点伤害；第一关所有敌人单次攻击和普通接触最多造成一格生命。若试玩需要调整，只能修改集中式 tuning 资源和对应断言，不能在场景或运行脚本中散落覆盖值。

## 5. 机械丝施放设计

### 5.1 状态机

机械丝使用以下显式状态：

1. `Idle`：可输入或处于冷却。
2. `Preview`：长按瞄准，显示候选、作用类型和阻挡结果。
3. `Windup`：线轴蓄能，手臂后撤，目标正式锁定。
4. `Travel`：丝梭按距离飞向目标。
5. `Latched`：菱形锁扣展开，进行短命中确认。
6. `Apply`：拉动玩家、拉动轻敌或启动机关。
7. `Recovery`：三股丝回收；允许被移动和跳跃取消。
8. `Failed`：显示无目标、遮挡、过远、冷却或目标失效原因，然后快速回到可控状态。

状态命名可在实施计划中与现有代码风格统一，但阶段和可见行为不得合并回“按键同帧立即结算”。

### 5.2 输入规则

- 按下不足 0.14 秒并松开视为轻按；达到 0.14 秒时进入长按预览。该阈值只存在于集中式机械丝配置中。
- 轻按 `K`：在 260 像素辅助范围、面向方向 55 度半角和真实视线内选择最高优先级目标，快速进入 `Windup`。
- 长按 `K`：进入 `Preview`；方向键或摇杆改变瞄准方向，在 400 像素能力范围和 30 度瞄准半角内选择候选。候选目标使用金色菱形，预计丝线使用低亮度青色。
- 松开：锁定当前有效目标并施放；没有有效目标时进入可解释失败，不消耗完整冷却。
- 预览不会冻结游戏，角色水平目标速度降为正常值的 65%；跳跃仍可用，闪避、受击和场景切换会取消预览且不消耗冷却。
- 目标优先级为机制/明确教学目标、可牵引轻敌、玩家移动锚点；优先级和距离仍受真实视线与配置约束。

### 5.3 表现时间

“清晰弹性”的初始目标节奏为：准备约 4 帧、甩出约 3 帧、飞行按距离约 0.08–0.28 秒、命中确认约 5 帧、收势约 7 帧。具体帧数以 60 FPS 为验收基准，并在实机中调整。

丝梭飞行时显示针头和一至三股跟随丝；命中后锁扣展开，再让丝线绷直。不得在同一物理帧同时开始、命中并清除。屏幕震动只用于重目标或强牵引，并服从可访问性设置。

### 5.4 失败与冷却

- 无目标：短促空转和收针，不绘制假命中线。
- 世界遮挡：丝梭在阻挡点打出小火花并回收。
- 超出距离：预览线在最大距离处断开，松开不进入完整施放。
- 冷却中：左上线轴环显示剩余时间，按键只给轻微反馈。
- 飞行中目标失效：在最后有效位置消散并进入短失败收势，不牵引错误对象。

## 6. 玩家与怪物动作系统

### 6.1 三层混合

- **基础移动层：** 待机呼吸、起跑、跑动、刹停、起跳、上升、滞空、下落、轻落地和重落地。
- **上半身行动层：** 地面攻击、空中攻击、下劈、机械丝、受击和恢复；移动时仍可播放允许的上半身动作。
- **次级运动层：** 披风、悬浮灯、肩部线轴和腐化挂件使用独立弹簧或曲线，读取速度、加速度、转向、落地与受击冲量。

当前逐帧恢复默认姿势再切换动作的方式被替换为关键姿势之间的短插值。行动层拥有准备、爆发、命中和收势时间，不因基础移动帧更新而丢失。

### 6.2 玩家动作清单

至少覆盖：待机、起跑、跑、刹停、起跳、上升、滞空、下落、轻落地、重落地、地面攻击、空中攻击、下劈、命中、落空收势、机械丝预览、蓄能、甩针、命中、牵引、失败、回收、受击、击退、死亡和检查点复原。

收势可以按每个动作的取消规则被移动或跳跃打断；准备和命中确认不能被无条件跳过。轻微命中停顿、局部闪光、受击方向变形和音效用于确认接触，但不能造成明显输入延迟。

### 6.3 资源替换边界

玩家资源插槽至少保持头、躯干、近/远手臂、近/远腿、武器、披风、肩部核心、悬浮灯、能量连接和丝梭独立。敌人保持主体、武器、腐化侧、挂件和特效独立。程序化部件与未来正式手绘部件使用相同插槽、轴点和动作接口。

## 7. 场景与怪物美术升级

### 7.1 五层房间结构

每个房间包含：

1. 远景：断钟塔、巨大钟影、通风井和远处机械轮廓。
2. 中景：旧石墙、木梁、铜管、悬钟、传动轴和房间识别物。
3. 游戏层皮肤：与真实平台、墙面、机关和敌人轮廓对齐。
4. 前景：少量梁柱、链条和碎片；进入遮挡关系时自动减弱，不遮挡攻击与目标。
5. 氛围：灰尘、蒸汽、孢子、微光和受控视差。

### 7.2 房间识别

- 苏醒庭院：冷色天光、破损钟面、开阔轮廓。
- 断齿走廊：近景齿轮、断轴和清晰机械丝教学目标。
- 上层摆锤区：纵向链条、摆锤影和高低平台。
- 下层机械区：锈铜管、蒸汽和中度腐化菌丝。
- 钟链房：巨大垂直钟链和金色目标形成视觉中心。
- Boss 房：宽阔地面、残钟背光、最低前景遮挡和最清楚的危险区域。

纹理使用低频材质变化，不用高密度噪点冒充细节。1280×720 实际视距下先通过大形、明暗和轮廓读取，再添加近距离纹理。

## 8. HUD 与音效

### 8.1 紧凑分层 HUD

- 左上仪表合并五格生命和机械丝线轴；线轴外环表示冷却，中心表示可用、预览、命中或失败。
- 当前目标默认一行显示，状态变化后短暂展开，再折叠为目标符号。
- 机械丝预览和机关操作提示靠近目标，但避开角色、敌人头部和红色危险区。
- Boss 名称、生命和阶段贴近底部安全区，不遮挡脚下地面。
- 第一关教学仅在首次触发、连续失败或玩家手动重开时展开；暂停菜单保留指导开关。
- 所有重要信息同时使用颜色、形状、动画或文字中的至少两种，不依赖单一颜色。

### 8.2 声音语言

- 蓄力、锁定、攻击生效和恢复使用不同声音阶段。
- 锈壳侍从偏金属摩擦与枪尖，墓灯飞蛾偏翼膜与灯鸣，背钟劳工偏链条和重锤。
- 机械丝包含线轴旋转、丝梭破空、锁扣咬合和三股丝绷紧四层声音。
- Boss 横扫、跃击、地面波和投锤拥有可独立辨认的起手声音。
- UI 音效保持短促，不与战斗预警争夺频段。

## 9. 退化与错误处理

- 正式视觉资源缺失时，开发构建使用结构一致的程序化替代物并记录命名警告；发布验收把可见替代物视为失败。
- 攻击描述无效、形状为负或时长不合法时，Builder/验证器失败，不生成误导性红区。
- 表现节点缺失时不得阻断玩法，但日志必须指出稳定节点路径与资源名。
- 机械丝目标失效、被释放或离开树时，状态机进入失败并清理引用，不能抛异常或牵引已销毁对象。
- 房间切换、死亡恢复和暂停必须清理预览、丝梭、危险区、命中闪光与临时音效，避免跨房间残留。
- 设置关闭强预警、震动或闪光时，只改变表现强度，不改变判定与敌人时间。

## 10. 验证策略

### 10.1 自动测试

- 单元测试覆盖攻击阶段边界、锁定位置、真实形状、机械丝输入分类、目标优先级、状态转移、取消、失败和冷却。
- Godot 集成测试覆盖真实碰撞、红区与攻击判定一致、丝梭飞行、目标失效、场景切换、死亡恢复、动画层和 HUD 绑定。
- 结构测试覆盖资源插槽、稳定节点路径、房间五层、碰撞层、UI 安全区和生成场景语义。
- Smoke 覆盖移动教学、三类普通敌人、上下路线、钟链、机械丝轻按/长按、Boss 三种攻击、锁链、失败恢复和完成。
- 关键 mutation 必须证明：删除预警、错配范围、同帧完成机械丝、清除失败反馈或跳过动作层时，测试会按命名断言失败。

### 10.2 可见验收

- 每个里程碑生成 60 FPS 确定性录屏，逐帧确认准备、危险区、攻击生效、机械丝四段、动作过渡、披风/灯具延迟、HUD 和房间层次。
- 验证 1280×720、1920×1080 以及当前支持的宽屏布局；HUD 不得遮挡角色、敌人、机关、攻击区或 Boss 地面。
- 日志不得出现 `ERROR`、`SCRIPT ERROR`、`Parse Error`、缺失节点、丢失资源或非法目标引用。
- 自动驱动只能作为确定性证据，不能写入或冒充真人试玩报告。

### 10.3 真人体验指标

每个主要里程碑都启动正常可见游戏供实际操作。最终候选版本的目标为：

- 首次玩家在约 10–15 分钟有效游玩时间内完成第一关。
- 普通路线预计死亡 0–5 次。
- Boss 预计 2–6 次尝试完成。
- 玩家能在攻击生效前通过姿势、范围或声音判断方向。
- 机械丝准备、飞行、命中和牵引在正常速度下均可见；对明确目标的首次使用稳定成功。
- 跑跳、转向、攻击、机械丝和受击之间无明显硬切。

指标是发现问题的门槛，不是通过削弱统计或伪造会话来达成。若真人仍无法通关或无法解释失败原因，目标继续保持进行中。

## 11. 交付里程碑

1. **攻击预警与难度：** 统一攻击描述、普通敌人和 Boss 三段预警、第一关参数重平衡。
2. **机械丝重构：** 混合输入、显式状态机、丝梭针四段表现、失败与冷却反馈。
3. **动作系统：** 三层混合、玩家完整动作、三类敌人与 Boss 独特姿势、次级运动。
4. **美术、HUD 与音效：** 暮钟工业遗迹五层场景、AC 中度腐化、紧凑分层 HUD、分阶段声音语言。
5. **完整体验与修正：** 两轮完整自动门禁、确定性录屏、真人 10–15 分钟游玩和问题修复。

各里程碑都必须保持游戏可运行，不积累到最后才首次集成。实现计划可以把独立资源和测试任务并行化，但同一场景或同一生成器的所有权必须唯一。

## 12. 持续状态与完成定义

README 持续维护四类状态：`已完成`、`正在优化`、`待真人复核`、`待正式素材替换`，并更新资产表、运行方式和最新证明。

本轮只有同时满足以下条件才能标记完成：

1. 第一关敌人攻击在动作、真实范围和声音上均可预判。
2. 机械丝轻按与长按均可稳定使用，四段表现清楚，失败原因明确。
3. 玩家、普通敌人和 Boss 的关键动作无明显硬切，次级部件具有连续惯性。
4. 六房间具备可辨认的多层场景，怪物采用一致的 AC 中度腐化语言。
5. 紧凑 HUD、教学、Boss UI 和设置在目标分辨率无重叠或长期遮挡。
6. 自动门禁、真实运行、录屏审查和日志扫描通过。
7. 真人完成固定版本的第一关，并确认难度、机械丝、动作与感官表现达到可继续迭代的水平。

任一项未满足时，持续目标保持进行中；不得以干净构建、自动录屏或旧进程代替最终实机体验。
