# 线轴承载者完整分层母版设计

**日期：** 2026-08-13
**状态：** 用户已于 2026-08-13 批准
**范围：** 重做角色静态分层母版；不制作动画，不发布运行时素材

## 1. 背景与结论

此前的 B 路线试图从一张已合成的正式身份图中裁出刚体、斗篷、武器和
遮挡补底。预检证明这种方法无法恢复原图中不存在的隐藏像素：斗篷层混入
硬件，鞋层夹带腿甲和绿布，部分轮廓被截断，内衬只能靠推测填补。自动测试
能够证明静止合成等于原图，却不能证明每件部件本身完整、归属明确或适合
动画。

因此 B 路线停止并保留为失败证据。新采用 C 路线：重新设计被遮挡的身体
结构，并制作一套真正完整的独立部件。允许重新设计隐藏结构和连接方式，
但必须保留已经锁定的角色身份。

## 2. 已锁定的角色身份

以下特征不能在新母版中漂移：

- 小体型、右侧朝向的横版游戏比例；
- 圆形骨白陶瓷头壳与青色目缝；
- 胸前占主导视觉的线轴核心；
- 宽阔、完整的半钟刃；
- 青绿、磨损、带破洞和金边的连续斗篷；
- 背部能量核心；
- 位于头顶偏后、与身体分离的悬浮灯；
- 陶瓷、深色布料、少量古旧黄铜和青色能量构成的材质语言。

过度写实的金属质感和少量复杂机械零件可以存在，但必须集中在线轴、核心、
扣件和关节等功能位置。它们不能重新造成满屏微型噪点，也不能抢走头部、
线轴、半钟刃和斗篷的视觉层级。

## 3. 双母版架构

本路线采用“方案 3：双母版逐件验收”。同一套素材必须形成四类审查输出：

1. **无遮盖结构母版**：完整头部、躯干、左右四肢和鞋。任何身体部位都不被
   斗篷、武器、前线轴或背部设备遮住。
2. **独立部件展开母版**：把所有身体甲片、装备、遮挡片和能量组件分别完整
   展示，任何单件都不能依赖邻件补齐轮廓。
3. **穿着身份母版**：用相同部件重新组合成正式右侧造型，用来验证新结构
   没有改变已批准身份。
4. **背部局部展开图**：明确显示背部核心、隐藏中轴、肩领、斗篷根部和能量
   丝线接口。当前 Demo 不制作没有运行需求的完整正面和背面三视图。

每类母版都提供透明背景版和棋盘背景审查版。无遮盖母版证明隐藏结构完整，
穿着母版证明身份一致；两者缺一不可。

## 4. 身体结构

角色内部采用已确认的 A 结构：陶瓷甲片、深色布质软关节和少量黄铜机构。

- 底层是一具连续、合理的人形软内体，不是装备移除后的空洞。
- 陶瓷头壳、胸甲、骨盆甲、左右上臂甲、左右前臂甲、左右手、左右大腿甲、
  左右小腿甲和双鞋分别完整。
- 左右上臂、前臂、手分件；左右大腿、小腿、鞋分件。
- 肩、肘、腕、髋、膝和踝后方设置深色布质重叠区，弯曲时不能露缝。
- 左右肢体必须在命名、展开位置和连接点上明确区分。

卸下所有外甲和装备后，软内体仍应呈现连续的小体型人形轮廓；装回甲片后，
轮廓回到当前陶瓷钟械造物的身份。

## 5. 胸背线轴系统

采用已确认的三层独立结构：

- 完整躯干；
- 完整前线轴外壳、可独立轻微旋转的线轴盘和单独发光层；
- 完整背部核心外壳、能量仓和单独发光层；
- 在背部展开图中显示连接前后设备的隐藏中轴。

卸下前线轴和背部核心后，躯干仍然完整。前线轴不能成为胸口缺洞的填充物；
背部核心也不能与斗篷像素粘在同一层。发光只能由独立能量层提供，不能漂白
陶瓷或布料主体。

## 6. 斗篷结构

斗篷采用已确认的 B 结构：

- 独立硬质肩领和扣件承担固定；
- 斗篷本体是一整片连续软布，不拆成机械铰链式碎片；
- 小型前领片独立处理胸口的前景遮挡；
- 斗篷单件必须包含完整外轮廓、破洞、金边、内侧布面和根部连接区；
- 硬件、手、腿甲、武器和背部核心的任何像素都不得混入斗篷层。

斗篷根部通过肩领连接，布面后续才可接受连续形变。当前阶段只证明布料与
连接结构完整，不制作摆动或波形动画。

## 7. 武器、手和握持关系

- 半钟刃是一件完整武器，包含完整刀柄、护手和刃身。
- 左右上肢和双手始终作为完整身体部件保留，不烘焙进武器层。
- 握持时使用独立的小型前景手指遮挡片覆盖刀柄。
- 遮挡片只负责层级关系，不能从手或刀柄主体上剪走像素。

这种结构必须同时支持待机、奔跑、地面攻击和丝线施法的后续组合，但本规格
不定义这些动作的帧数或姿态。

## 8. 悬浮灯与能量丝线

- 悬浮灯是一件完整独立道具，并有独立发光层。
- 背部核心和灯具互不借用像素。
- 能量丝线分为背部连接端、发光中段和灯端连接点三部分。
- 丝线可在未来独立弯曲、闪烁或减弱，不烘焙进身体或灯具。
- 灯具静态位置在头顶偏后，与头壳轮廓保持清晰间隙。

## 9. 唯一归属与遮挡合同

每个可见像素必须具有一种明确的主体归属。完整主体和为构图准备的遮挡片是
不同概念：主体永远保存完整轮廓，遮挡片只在组合时覆盖其局部。

强制规则如下：

- 每件主体必须先在无其他部件覆盖的情况下完整展示。
- 同一主体不能靠相邻部件的像素补齐自身。
- 一个图层不得混入其他部件；尤其禁止将手、腿甲、金属扣件或核心混入斗篷。
- 前后关系通过图层顺序和专用遮挡片处理，不从主体上永久删除像素。
- 活动连接处可以有真实重叠区，但审查图必须分别标出主体边界、连接点和重叠
  范围。
- 任何无法确定归属的区域都必须停止并重新设计，不能通过模糊、拉伸、复制
  纹理或颜色传播掩盖。

## 10. 免费制作流程

新母版按以下顺序制作：

1. 制作低细节结构稿，只解决比例、部件完整性、连接点和前后层级。
2. 结构稿批准后，以本地数字绘制流程逐件绘制完整部件。现有身份图只作为
   色彩、材质、比例和轮廓参考，不再直接裁切成“完整”隐藏部件。
3. 分组提交：内体与陶瓷甲片 → 胸背线轴系统 → 斗篷 → 武器与手 → 悬浮灯
   与能量丝线。
4. 所有独立部件通过后，重新组合穿着身份母版并检查 96 像素游戏尺寸。
5. 静态母版全部批准后，才允许 Agent Sprite Forge 或 `sprite-gen` 进行无损
   组合、动作轨道、切片、对齐、图集和质量检查。

Agent Sprite Forge 和 `sprite-gen` 不承担原创隐藏结构或自动补全职责。它们是
后处理工具，不能把缺失的原创绘制变成可靠部件。

## 11. 费用和生成边界

- 默认只使用本地免费工具和人工式数字绘制步骤。
- 不调用付费图像 API，不自动消耗宿主图像生成额度。
- 如果免费本地绘制无法达到当前身份图的材质和完成度，必须展示差距并停止，
  不能把低质量结果标为正式素材。
- 未来任何生成式修补都必须先说明具体用途、输入输出范围、是否计费或消耗
  额度，并重新取得用户明确批准。

## 12. 审查关卡

每一关都需要用户明确批准，自动检查不能代替视觉判断：

1. **结构线稿关**：检查无遮盖身体、左右肢体、活动连接点和背部展开结构。
2. **独立部件关**：在统一棋盘背景上逐件检查完整轮廓、唯一归属和无混入。
3. **穿着复原关**：组合全部部件，核对体型、剪影和全部身份标志。
4. **小尺寸可读性关**：同时检查原尺寸和约 96 像素身体高度，限制噪点。
5. **动画准备关**：只检查关节重叠、前后层级和斗篷连续性，不制作正式动作。

通过全部五关之后，另行编写动画设计和实施计划。本规格不继承被拒绝的
12 帧待机时间表，也不预设新的动画帧数。

## 13. 失败条件与返工边界

出现以下任一问题，当前部件组立即退回：

- 部件缺失、边缘截断或依赖其他层补齐；
- 一个图层混入其他部件；
- 左右肢体无法明确区分；
- 隐藏结构靠模糊、拉伸、复制纹理或推测性填充蒙混；
- 穿着后角色身份发生明显变化；
- 约 96 像素尺寸下噪点过多，或重新出现强烈 AI 生成感；
- 免费本地流程达不到当前母版质量。

返工只修改失败的部件组。已经批准的部件、比例、颜色和连接点不得随其他组
返工而漂移。如果基础结构的变更不可避免地影响已批准部件，必须先说明影响
范围并重新进入相应审查关。

## 14. 产物边界

结构稿、独立部件、母版和审查图保留在外部美术工作区；在静态母版全部批准
之前，不替换以下运行时文件：

- `assets/player/thread-spool-bearer/player-atlas.png`
- `assets/player/thread-spool-bearer/player-atlas.json`
- `assets/player/thread-spool-bearer/player-animations.tres`
- `scenes/player/Player.tscn`

旧的裁切预检、被拒绝的待机动画和相关诊断图继续保留为失败证据，不作为新
母版的像素来源。

## 15. 完成定义

C 路线的静态母版阶段只有在以下条件同时成立时完成：

- 无遮盖身体连续、完整，所有左右肢体和连接点明确；
- 所有主体部件均能独立完整展示且像素唯一归属；
- 背部展开图解释前线轴、背部核心、肩领、斗篷和悬浮灯的连接关系；
- 穿着身份母版保留已锁定身份；
- 原尺寸与约 96 像素尺寸均通过视觉审查；
- 用户逐关明确批准；
- 没有调用未经批准的生成或付费服务；
- 没有发布动画、图集、Godot 场景或运行时替换素材。
